# 10 · UI / UX 与前端实施规范

版本：2.0.0；日期：2026-09-30；设计默认已在本包确定，产品界面尚未实现。负责人 W13，设备与手机正式门归 W17，发行截图归 W20。

本文件、contracts/ui.contract.json、ui/design-tokens.json 共同定义前端交付。ui/reference.html 是离线设计参考板，所有数字均为 FIXTURE，不接服务、不代表运行成果。规范发生冲突时，字段/状态依机器合同，布局与交互依本文件，参考板只帮助理解视觉。

## 1. 设计方向

采用安静、可长时间阅读的研究工作台：暖白/浅灰底、细边框、深灰文字、少量深绿强调；提供完整深色主题。成果、证据与决定优先，普通技术日志展开后看。这里的配色与尺寸是可执行设计默认，不宣称用户逐项选定或经过用户测试。

来源分工：Craft Agents 借鉴任务—会话—文档的组织；Midday 借鉴克制排版；Linear 借鉴变更与检查一起审查；Scira 借鉴可定位引用；Plane/Twenty 借鉴列表筛选；LobeHub 借鉴Agent/项目目录。DSH-soup 提供侧栏、预览与目标栏思路，PentAGI 提供执行过程和证据同屏思路。使用自己的名称、图标与页面文案，代码复用逐文件核查许可。具体历史证据见 references/Frontend_Research_2026-09-29.md。

首版不做办公室动画、3D员工、装饰性节点大屏或整页聊天气泡。图形只有在表达任务依赖、来源覆盖或对比结果时使用，不能替代可检查数据。

## 2. 页面结构与导航

| 屏幕 | 地址模式 | 用户要完成的事 | 首屏内容与主要动作 |
|---|---|---|---|
| S00 项目入口 | / | 导入默认ResearchOS，提出想法 | 项目列表、想法输入、已有资料、可用运行器/来源状态；创建Goal并展示系统整理的范围 |
| S01 工作台 | /p/:projectId | 迅速知道发生了什么 | 持续目标、当前周期、阻塞、下一步、最近已验收成果；打开任务/成果 |
| S02 研究周期 | /p/:projectId/cycles/:cycleId | 看候选如何变成采用决定 | 三类来源覆盖、候选、核验、实验、评审、交付、跟踪；来源缺失有原因 |
| S03 任务详情 | /p/:projectId/tasks/:taskId | 查看执行与产物、控制任务 | 摘要/过程/产物/检查标签；当前Run、执行器、输入版本、耗时；暂停/恢复/取消 |
| S04 成果与审查 | /p/:projectId/releases/:releaseId | 理解本次变化是否可靠 | 摘要、改变、采用理由、原始证据、实际测试、限制、下一步；版本选择及受控下载 |
| S05 来源证据库 | /p/:projectId/evidence | 查依据、判断是否过期 | 来源类型/日期/有效性/独立来源筛选；正文定位、抓取时间、hash、传播关系 |
| S06 实验与评测 | /p/:projectId/experiments/:experimentId | 比较基线与候选 | 假设、冻结条件、指标、完整性、基线/候选并列、负结果、费用；资格单独显示 |
| S07 知识与技能 | /p/:projectId/knowledge | 查看学到了什么及能否使用 | 来源覆盖、候选/稳定版本、评测与撤回；无权限的晋升按钮不出现 |
| S08 团队与运行器 | /p/:projectId/team | 看谁在做什么、是否真实可用 | 已注册运行器、职责、当前Task/Run、probe/live/资格分别展示；不捏造在线员工 |
| S09 费用与资源 | /p/:projectId/resources | 判断花费和真正需要处理的事 | 已知消费、在途预留、未知项、金额策略、去重资源请求；修改上限、解决请求 |
| S10 设置与设备 | /p/:projectId/settings | 管理运行策略与手机 | 来源配置状态、周期/并发策略、设备列表、配对及撤销；凭据正文不返回前端 |

列表/详情可共用页面组件，桌面任务详情可在主区打开；URL必须可直接进入与恢复选中项。根目录导航和深层路由刷新不能404。每次切项目取消旧请求或校验响应project_id，避免串入新页。

设置页来源配置先实现声明式配置与健康展示；密钥输入通过受保护的服务入口完成。若某设置动作尚无本包公开API，按12的命令绑定/资源指南实现本地受保护设置流程并登记，不能在前端虚构一个成功API。

## 3. 布局尺寸与响应式

| 范围 | 布局 | 行为 |
|---|---|---|
| ≥1280 CSS px | 左导航216px，中央最小560px，右进度280px；顶部56px | 左右可收起；中区正文最大1040px，任务/证据表可更宽；右侧始终能找到阶段和成果 |
| 768–1279 | 左导航64px或抽屉，中央优先，右进度抽屉 | 抽屉有关闭按钮、Escape与焦点回归；同一时刻保持可理解的层级 |
| <768 | 单列；顶部项目/目标/进度按钮，底部主要导航 | 阶段、文件树、筛选用独立抽屉；表格改摘要行+详情，代码区域局部横滑 |
| 320px与200%缩放 | 关键动作和文本仍可用 | 应用主体不横溢；长ID省略可复制，中文标题换行，禁止只靠悬停才显示内容 |

主要页面使用4/8px间距体系；正文14–16px、行高1.55–1.65；标题24–28px；辅助信息至少12px，重要状态至少13px。系统字体优先，中文使用系统可用字体。数字使用等宽数字，代码采用系统等宽字体。token文件是颜色、字号、半径、动效和尺寸唯一来源。

默认浅色；记住用户主题选择，仅主题偏好可本地存储。不要在localStorage保留凭据、受限报告或业务权威状态。深色主题全量覆盖，状态颜色须适配背景。尊重prefers-reduced-motion；正常动效120–180ms，只用于反馈与面板切换。

## 4. 核心组件合同

| 组件 | 输入与责任 | 交互/错误规则 |
|---|---|---|
| GoalBar | 当前Goal、范围revision、当前阶段/下一步 | 多行可展开；修订产生ChangeProposal，不直接覆盖接受事实 |
| StageRail | ProgressProjection六阶段计数、plan_revision、事件水位 | 显示已验收/计划、进行中、待评审、阻塞；计划变化注明原因；没有分母不显示百分比 |
| TaskRow/TaskDetail | Task、Run、RuntimeRegistration | 运行结束和已验收分开；暂停/取消为服务端动作，等待回执期间防重复提交 |
| ActivityTimeline | EventEnvelope、关联Run/Artifact | 按event_id去重；技术详情折叠；一段token输出不生成一条重大通知 |
| EvidenceChip | 固定Evidence引用、独立源、有效性 | 点击能定位到原文；引用缺失、过期、转载、无法访问有明确标签 |
| ArtifactPreview | artifact_id/revision/content_hash/access_class | 先验证访问权；加载失败可下载；受限内容禁止通过缩略图/标题/缓存泄露 |
| ReviewPanel | MilestoneRelease、AcceptanceReceipt、DecisionReceipt | 展示冻结检查、真实命令、失败和限制；模型分数与程序检查分区；不提供绕过服务端的“一键验收” |
| EvaluationCompare | EvaluationSummary，开发集时可授权加载Report | 基线和候选在同一指标定义下比；errors/abstain/missing独立；正式holdout不显示逐题详情 |
| ResourceCard | ResourceRequest、BudgetPolicy、BudgetLedgerEntry | 缺什么、已做什么、影响什么、恢复条件；只为真实缺口请求用户 |
| ConnectionBanner | 实际连接状态、最后同步时间与水位 | 离线冻结业务动画并标数据可能过期；重连后校验最新快照 |
| CommandFeedback | 实际HTTP/操作状态、request/correlation ID | 202仅表示请求接收；409冲突/412过期保留草稿并提示合并；失败提供原因和重试范围 |

首版预览支持Markdown、HTML、图片、PDF、JSON/CSV和代码。默认行内上限5MiB，超出改分块/下载；这是可调整工程默认。HTML默认无脚本，以独立受限iframe与CSP隔离，不启用allow-same-origin+allow-scripts组合，不自动加载外部网络；Markdown清理不可信HTML。PDF/图片失败给受控下载。Notebook先展示静态内容，不执行单元。

已封存Artifact不可原地编辑。草稿编辑写入候选，保存携带基线revision/hash；409/412保留本地草稿及外部版本，走合并后重验。禁止DSH-soup式更新基线后用旧内容自动覆盖。

## 5. 状态与文案

contracts/ui.contract.json定义全部Task/Run标签，不发明API状态。Task没有PAUSED枚举，暂停效果依据服务端合同中的BLOCKED/原因及Run过程展示；不能前端追加PAUSED写回后端。

| 情况 | 必须显示 | 主要动作 |
|---|---|---|
| 新项目/无Goal | 尚未开始；说明输入一个想法即可 | 创建Goal，自动从已知背景整理范围 |
| Loading | 局部骨架与加载状态 | 超时变成可解释错误；不能永久旋转 |
| 来源空集 | 查询成功，本窗口无新候选 | 显示查询范围与时间 |
| X鉴权/限流/不可访问 | 来源覆盖PARTIAL/受限及原因 | 合法配置/稍后重试；其他来源继续 |
| 待评审 | 已提交执行结果，验收尚未完成 | 查看产物与检查；不计入已验收 |
| 输入过期/冲突 | 版本已变化，需要合并或重验 | 查看差异、保留草稿、发起重验 |
| Offline/重连 | 最后同步时间，状态可能过期 | 重连；写动作禁用或明确待确认，不乐观假成功 |
| 限额未设 | 未设金额上限 | 查看消费/预留；不表示余额无限 |
| 费用未知 | 待结算/供应商未提供 | 可查看未知来源；不补成0 |
| 实验无改善/拒绝采用 | 合法结论及证据 | 保留稳定版本、登记下一问题 |

费用、覆盖率、进度和质量分别展示，不把一种百分比代替其他维度。日期显示用户时区和相对时间，详情保留UTC；“刚刚”也能查看确切时间。

## 6. 交互验收与视觉取证

C23覆盖全部11个屏幕的操作/状态，C24覆盖双主题、5个视口、200%缩放、键盘和减弱动效，C25覆盖预览与冲突，C26覆盖事件恢复。A10/A11/A15继续要求真实Windows与手机相关验证，夹具浏览器截图不能替代。

界面完成后至少交付：工作台/周期/审查/证据/评测/资源的桌面双主题截图，390px工作台/任务/资源/设备截图，键盘操作记录，离线/冲突/待评审状态截图。逐项实际检查；截图不是业务验收的独立充分证据。

UI具备清晰的可见焦点、原生语义控件、可读label、标题层级；主文本对比度≥4.5:1，大字/关键图形≥3:1；主要手机触点≥44×44 CSS px。无障碍属性要与真实状态同步，通知避免重复打断读屏。

本包参考板仅已定义页面外观与模拟交互。交付代码必须接真实合同与事件，并通过上述用例。
