## 1. 产品是什么

ResearchOS是自己的Agent产品，交付两个正式入口：`researchos` CLI/TUI和ResearchOS Desktop。两者共享Agent核心、项目、会话、模型配置、工具、权限、Goal、费用与验收记录。研究GitHub/X/论文、Jev判断、持续续跑、团队协作和自身改进，是这个Agent的内置能力。

用户可以在项目目录打开CLI，用自然语言要求查看代码、修改文件、运行测试或完成一个长目标；也能打开Desktop，通过会话、工具流、文件树、diff和成果预览处理相同工作。首版仍默认Windows 11 x64。原生手机App后置，已有手机监督网页作为辅助入口保留。

自己的产品允许以开源项目fork、源码模块复用或SDK组合实现；关键是我们有可安装入口、固定版本、可维护改动、实际能力与独立验收。找到合适实现并判断采用后，直接在其代码基础上适配，避免看完设计又重写同类系统。是否适合必须有源码、验证、Jev建议和独立接受依据；不是发现仓库就全部clone进主工程，也不以改名截图或能唤起外部CLI作为成品。

## 2. 优先复用路线

### 2.1 先验证现场已有实现

W00盘点实际授权本地目录、依赖、技能、工具、SDK、CLI和桌面代码；如果已有合法ResearchOS实现，先接续并做差距评审。路径和项目身份必须实读。当前会话已缓存Mu、QM、last30days源码和调研；这只是本会话资产，不能声称已经扫描用户Windows电脑。

### 2.2 两条有界复用路线

下表为有界资格比较的候选起点，不是预先批准采用。按15/16先核对需求与本地方案，再检查来源、许可、平台、实测能力及适配成本；Jev参与结构化建议，实际采用由硬门和独立接受决定。临时clone检视源码与正式fork/集成分开记录。

| 路线 | 固定起点 | 首要实验 |
|---|---|---|
| `MU_FORK`，优先验证 | Mu commit `8dfebe36508ac0c2508735bb866756dab9283e74`中的CLI、Jev、Desktop完整组合 | 构建自有CLI与桌面样机，验证同一会话双端接续、文件/工具操作、取消和恢复 |
| `PI_COMPOSE`，复用备选 | Pi候选`v0.99.2`，先解析实际commit；复用已找到的桌面壳/组件与本地存储 | 以Pi SDK/协议承载共享核心，用窄适配接桌面；复用已有终端/UI/打包能力 |

每条路线最多一次针对已观察失败的修复，不反复叠加第三套主控。只有现成路线确实不满足某项能力，且15规定的缺口证据齐全，才允许`GAP_ONLY_COMPOSE`：仍复用成熟模型SDK、终端、桌面壳和存储，只新写缺口模块。缺机器、账户或网络属于资源阻塞，不构成“没有现成代码”的证明。

QM降为按需可选远程适配或可靠性机制参考。其当前CLI用于部署，Desktop连接已部署Web服务；它们不能直接替代本产品本地CLI Agent和带运行能力的Desktop。无需让用户先部署QM/Postgres才能打开本产品。

Mu判断/CLI代码根许可MIT，`desktop/`为Apache-2.0，保留各自声明与AionUi来源。Mu源码中内嵌Pi为0.87.1，独立Pi候选0.99.2不直接覆盖它；QM未被选用时无需携带其0.82安全补丁依赖。component_lock记录实际选定组合，按需而非全量安装。

### 2.4 判断后采用，落实到可运行源码

同一套流程既用于建设ResearchOS，也用于建成Agent在项目内的调研与实施。按能力决定整仓fork、源码模块、固定库/SDK、本地复用、不采用、观察/补证或最小缺口自研；保持当前可用实现也是合法结果。采用后交付真实源码/依赖锁、修改位置、来源与许可、适配diff、关键测试和回退证据，不能以“调研完成”“clone完成”替代实现。

Jev本用途为`reuse_selection`，建议附固定输入与来源、适用模式、依据与拒绝/弃权理由。Jev高分不得覆盖失败硬门；没实际调用显示NOT_RUN，资源受阻显示BLOCKED，不把fixture当live。未取得本用途自动资格时只作SHADOW/ADVISORY，不能继承其他判断用途的资格，也不能自动扩大执行或发布权限。完整字段和接受规则见16及`contracts/adoption.schema.json`。

W00/W01可在已有授权下记录预资格ADVISORY；缺服务时仍推进本地盘点、源码检查、资格样机和接口骨架。W01不依赖后置W11，早期有界路线通过确定性检查及独立评审接受。W08冻结建议与接受的fixture协议，W11/W14闭合真实Jev及采用/拒绝的项目演示；真实判断未闭合时不能宣称该产品能力完成。

## 3. 共享核心与客户端边界

一个共享核心负责会话、Agent循环、工具准入、项目状态、任务归属、预算、事件和最终验收；多个会话可以有多个隔离worker，但同一会话只有一个有效写入owner。CLI和Desktop只经相同服务边界发指令、订阅事件，不分别拥有一份可独立派单的业务数据库。

优先复用上游会话存储和协议。ResearchOS领域状态默认本地SQLite，受单一服务控制事务；原始会话日志可保持上游格式并与本域ID映射。锁定迁移、备份和事件水位。不能一边保留上游可写状态、一边复制一份互不同步的状态供客户端修改。

`contracts/product.contract.json`定义客户端命令、必需操作和验收映射；`contracts/client.protocol.schema.json`定义本产品本地命令、响应、事件和正向复用计划；`contracts/adoption.schema.json`定义候选证据与采用裁决内容，通过现有Artifact/DecisionReceipt引用关联。它们是待实现的ResearchOS合同，不冒充Mu/Pi原生接口，不新增第二套领域实体或客户端命令。W02把原生方法映射到合同，W03/W05实现处理器，W13消费同一合同。

本地可用受鉴权named pipe/socket或loopback。请求绑定协议、command_id、client_id、project/session、expected_revision和writer_epoch；参数与身份由宿主检查。相同command_id同请求返回原回执，同键不同请求拒绝；旧revision/epoch不能覆盖当前任务。共享代码不等于任意客户端拥有任意权限。

`session.send`支持NORMAL/STEER/FOLLOW_UP；接收成功只表示入队，不表示工具已运行或任务已完成。事件包含session序号、run/command关联、核心版本及类型。重连按水位重放，缺口读取快照；token/工具/Jev细事件与现有业务EventEnvelope关联，不重复记费。

`session.handoff`在同一事务中转移写入权；忙时先在可中断点停止/暂停并确认，不能让两个Agent同时改同一工作区。旧客户端可保持只读订阅。多个独立任务沿用worktree、租约和共享文件owner规则。

## 4. CLI首版要求

用户安装后能直接运行`researchos`进入交互会话；当前目录可识别为项目，首次使用可选择/初始化项目。支持多行中文输入、流式回复、工具过程、错误原因、状态和键盘中断，长输出可展开/保存。至少实现：

| 入口 | 行为 |
|---|---|
| `researchos [--project <path-or-id>]` | 交互TUI；自然语言提出、执行和查看任务 |
| `researchos init <path>` | 建立项目身份并进入15/16规定的本地→研究→有证据判断→源码复用/适配流程 |
| `researchos run <prompt> --project <id> --output jsonl` | 非交互运行；stdout只有可解析事件，日志走stderr |
| `researchos goal <text>`、会话内`/goal` | 创建有完整合同的持续目标；继续/阻塞/完成均有证据 |
| `researchos resume <session-id>` | 接续同一身份、上下文和检查点；检查写入owner |
| `researchos status`、`cancel` | 查看真实状态或发取消，等待实际确认 |
| `researchos doctor`、`config` | 检查能力/模型/本地宿主并引导设置；凭据不打印 |

语法为本产品初始合同，W02可以通过明确版本化映射适配现有CLI；不得把未实现命令留空并报成功。交互还需`/help`、`/model`等常用入口。用户固定模型不能被路由器静默更换。

最小真实能力包括：读取授权文件、搜索、提出并落盘修改、查看diff、运行构建/测试、依据结果继续、封存产物。文件路径和副作用由程序限制。Skills/MCP接入复用已存在能力并分项探针；通用读写/命令执行由真实工具实现。

研究与实施过程中，CLI输出可追溯的候选、实际采用/拒绝理由、Jev运行状态与模式、硬门结果、源码/依赖位置、适配diff和验证回执。详细原始证据经既有Artifact入口查阅，常规会话只展示与当前决定有关的摘要。候选排序、正式接受和功能验收分别显示；不新增一套仅在CLI存在的选择状态。

结构化模式退出码：0为执行结果已报告，1为执行/检查失败，2为输入或配置错误，3为资源/授权阻塞，130为用户取消。正式完成另读AcceptanceReceipt。Ctrl+C和Desktop取消走同一停止链；清队列、等待settled、核对子进程，不把父进程退出当工具停止。

## 5. Desktop首版要求

交付有独立名称和图标、可安装并直接启动的Windows应用，携带必要运行时。开发阶段可以通过源码启动，但最终验收必须用安装包；用户无需先安装Node、打开终端、启动QM或手动拼接本地地址。

首次使用：选择/创建项目目录→配置已有授权模型端点→显示实际连接结果→进入Agent会话。没有模型资源时保留目录/历史浏览与配置能力，明确指出缺口。离线可读已保存的会话/文件/结果，不承诺云端模型离线推理。

保留10定义的11个视图，但主体验以工作为中心：S00项目入口含本地目录和初始化进度；S01主区为真实Agent会话，侧栏显示项目/会话、文件和Goal进度；S03展示运行与控制；S04展示文件、diff、产物和验收；S10设置模型、工具、核心与桌面行为。研究/来源/评测是同一应用中的功能页。

在既有视图中展示判断与源码采用，不增加页面：S00显示本地、调研、判断和适配阶段；S02对比保留现状与候选、采用范围、采用/拒绝/观察/待补证理由；S05可定位源码revision、许可和实测证据；S06分开展示Jev实际调用/资格、建议和程序检查；S04显示实际引入文件、来源与适配diff、验证及回退。Jev NOT_RUN/BLOCKED必须可见，高分但被硬门拒绝的候选保留拒绝原因；缺数据不显示虚构分数或收益百分比。

文件选择器、系统菜单、窗口尺寸记忆、快捷键、可见焦点、复制/搜索、受控文件打开、错误反馈和双主题均可操作。关键动作能直接从界面完成，不让用户到日志或终端猜命令。危险写入仍遵循已授权范围，界面不自动扩大权限。

renderer不获得通用Node/shell/fs或读取已存密钥的入口。通过受限preload/桥调用具体操作，验证sender/frame、参数和项目范围；外链交系统浏览器，不可信HTML/PDF预览维持隔离。首次配置允许受控、遮罩的临时密钥输入，提交后清除；凭据存受控后端，不写会话或日志，后续仅返回配置状态和脱敏引用。

关闭窗口、缩至托盘、显式退出和后台运行分别有明确设置/状态：已确认持久宿主才能声称任务继续；没有宿主支持时先保存检查点并显示暂停。renderer崩溃不等于业务失败或完成；重开先对账。人工取消/退出停止策略不能被自动续跑绕过。
