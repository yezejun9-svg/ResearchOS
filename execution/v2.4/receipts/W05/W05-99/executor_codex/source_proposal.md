## Behavioral decisions for review

### CLI event/completion contract

Use real session.events pages after the last observed sequence, following has_more/next_sequence until caught up, then poll with context and a bounded overall deadline. Each genuine host event is written as one JSONL record; diagnostics/prompts go to stderr. Preserve complete event payloads within protocol bounds, route long output through existing artifact reference, detect sequence gaps/foreign IDs and recover via real snapshot when retention requires it. Never synthesize token deltas from final text.

Capture target Goal/Task from the admission snapshot and Run when assigned. Do not let an old terminal Run or later unrelated session task satisfy this invocation. ACKNOWLEDGED/IN_PROGRESS/COMPLETED(method) are not execution success. Exit 0 only after the canonical result is fully reported and true settlement is observed; still report independent acceptance pending. Map FAILED to 1, invalid input to 2, missing resource/authorization or unresolved outcome to 3, confirmed user cancellation to 130. A deadline/disconnect with incomplete settlement is non-success and UNKNOWN/WAIT_FOR_SETTLEMENT, with session/run identity retained.

On Ctrl+C, cancel the local wait, refresh the current snapshot and send host session.control(CANCEL) with current valid revision/epoch and original target. Do not retry stale mutating commands blindly, take over another writer, kill unrelated processes or conclude stopped from exit 130. Wait boundedly for current canonical cancellation confirmation, children_stopped, queue_empty and reconciled effect projection. If signal occurs after Task admission but before Run exists, current host only accepts Run cancellation: retain a typed unresolved cancellation (non-success), and declare the exact host Task/Goal cancellation extension a follow-up gap rather than inventing a Run id. A04 pending_queue_cancel cannot PASS until that gap is actually closed.

Interactive input is processed while the process remains open; no EOF prerequisite. One admitted turn is followed to settlement before another NORMAL is submitted. Slash commands use the same handlers; multiline Chinese input needs an explicit submit boundary. Mid-run STEER/FOLLOW_UP durable queue is currently NOT_IMPLEMENTED in host and remains an explicit U02 gap until a separate exact queue scope is reviewed. Do not silently discard or spawn a second writer. Initial slice is not a complete TUI qualification; fold/expand and live steering stay separately measured.

### Explicit Goal bridge

The schema payload has only objective, contract_artifact_ids, start_as_draft; it cannot accept invented workspace/model/epoch fields. CLI can use existing session.create/get before goal.start when it has legitimate saved workspace/model refs; no manually copied token is allowed. Direct project-level requests require authenticated Owner and a real session selected from current host-authorized project bindings. If no unique usable binding is available, reject RESOURCE_BLOCKED with recovery detail; do not guess another model/workspace/client or fabricate a snapshot. Existing-session requests must pass writer CAS, ownership, lease, archived and unsettled-turn gates.

Contract artifact IDs must resolve to exact current effective project Artifacts with verified sealed bytes, not just user text or filenames. Non-draft must use real nonempty mandatory checks with EXACT/independent-verifier policy through freezeGoalContract. Draft does not submit/admit/start a worker. Extraction format and default contract provenance for empty contract_artifact_ids have no verified existing implementation: reviewer must choose an existing lawful contract producer or approve the narrowly defined decoder before non-draft is implemented. An empty artifact list is not permission to invent user acceptance checks. This is an explicit blocker to full natural-language goal <text> satisfaction, not a reason to weaken the frozen schema.

The adapter must retain objective and contract provenance in current Requirement/Goal/Task records, reuse createGoal/createTask/createContext/orchestrateTask and fixed MU admission, and retain the stable origin_problem_id/candidate_id/input_hash lineage when continuation is intended. It may not call sendClientMessage unchanged and inherit its random new problem identity for a retry. Already cancelled/UNKNOWN executions cannot be revived by a new Goal id. goal.start return COMPLETED only means Goal establishment; report goal_status and true snapshot, never ACCEPTED.

### Tool flow and costs

Emit TOOL_STARTED after authority/revalidation and before actual RunTool, carrying stable task/run/tool/effect correlation permitted by existing event schema. Emit TOOL_RESULT from durable confirmed/not-applied facts, with exact provenance and bounded artifact references. On interrupted result persistence retain UNKNOWN and original effect reservation; never invent a successful tool result or settle cost from SDK placeholder zero. Model-token streaming remains absent because broker buffers full SSE; initial construction claims only actual incremental host-tool/results/events. H08 nested run identity, shared budget/cancel, usage projection and security patch matrix remain mandatory qualifications with explicit evidence, not implicit consequences of this helper.
