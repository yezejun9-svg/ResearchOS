# W13 backend development evidence

`RESEARCHOS_TASK_ID=W13 python ops/ci/ui_backend.py --suite all` executes the backend subset over real loopback HTTP and SQLite. `--suite C17`, `C18`, `C25`, or `C26` selects only that backend coverage. Set `RESEARCHOS_GO` to the pinned Go executable when running in a worktree.

Passing this suite is not browser, mobile, W13-G02, or final W13 acceptance. The full C17/C18/C25/C26 cases also require their UI interaction and screenshot evidence; those remain partial until independently reviewed with frontend evidence. W05 live qualification is not waived.

The projection has six fixed stages. It derives from current domain objects, accepted task/contribution bindings and immutable Task history, in the same transaction as ProjectState's event watermark. `plan_revision` starts at 1 and advances once per Task creation or planning-field change (title, stage, goal, requirements, inputs, dependencies, stop policy, acceptance contract hash). State, executor, outputs and verification changes do not advance it. Consequently six separately created tasks yield revision 7 and three more yield revision 10; the numbers are not hardcoded plan batches. Cancelled tasks remain in the plan denominator; they are not accepted, active or pending review.

Task `VERIFYING` is a frozen enum but W06 does not currently expose the `EXECUTION_REPORTED -> VERIFYING` transition. The C18 fixture first reports through the actual API, then explicitly installs two schema-valid VERIFYING revisions with immutable history. All four ACCEPTED tasks go through the real independent acceptance service. No accepted status or passing receipt is fabricated.

SSE uses Bearer authentication and `Last-Event-ID` as a decimal project sequence. Without that header it starts at the current watermark. Fetch `/progress`, then subscribe with its `as_of_event_sequence` to cover snapshot-to-stream races. Events older than the 24-hour transport window require a 410 snapshot recovery. The outbox and historical evidence are retained. A cursor already at the current watermark remains valid even if the last event is old. Messages use `id`, `event: message` and an EventEnvelope `data` value; the real 15-second comment heartbeat never advances sequence. Permission filtering can legitimately skip global sequence numbers; clients reconcile with a snapshot rather than requiring a hidden event to be disclosed.

Release creation binds current independent Task, Goal or applied ChangeProposal acceptance. Release, current project pointer, notifications and outbox events commit atomically. Notifications are sent only in-app to active project-wide OWNER/READER recipients with release visibility; they are readable only by their recipient. An existing notification is not created again during replay. Marking an already-read notification preserves its revision, read timestamp and event sequence.

Security fixtures contain explicitly synthetic protected metadata, never formal holdout bytes. The actual protected content path remains unavailable until W17. Header checks demonstrate the server's attachment/CSP/hash behavior; browser execution, preview rendering, large-file UX and conflict editing are frontend evidence, not claimed by this suite.
