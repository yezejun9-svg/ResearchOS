# 07 · 运维、恢复与自主迭代

版本：2.3；日期：2026-10-01；产品运维演练与真实运行：`NOT_RUN`。

本文的数值是首版工程默认，可经配置变更记录调整，不是已经达到的服务等级。所有实际命令由 W02 写入并验证 `execution/commands.json` 及对应脚本；以下描述逻辑动作与证据，不虚构第三方 CLI。授权沿用当前项目范围，常规可逆维护与符合已授范围的发布自动推进，真正超范围才形成具体请求。

## 1. 部署和运行身份

首先读取 `execution/route.json`。只运行所选Mu/Pi复用组合的共享核心；禁止恢复时同时启用备用路线。备份方案、连接串、迁移工具与启动过程都由该文件确定。

| 部件 | 运行身份与写范围 | 崩溃后的恢复责任 |
|---|---|---|
| 稳定 supervisor | 受限制系统服务身份，维护发布槽、健康检查、回滚指针；不承担研究业务派单 | 自身由 OS 服务管理器恢复；候选无权卸载/改写 |
| 控制面 | 唯一调度/权威 API 身份；访问选定数据库与对象索引 | supervisor 先检查实例锁、版本与数据兼容性，再启动 |
| Worker | 仅允许项目工作区、任务临时目录、进程 journal | 启动时上报未结运行，等待控制面对账，不自行重派 |
| 执行器 | 任务范围、短时凭据、被分配工具 | 按 RuntimeAdapter 恢复能力续会话或重建 ContextBundle |
| 独立 verifier | 只读封存输入/产物、可写验收回执 | 未完成评审可重跑，不修改原始产物 |
| 只读来源/检索侧车 | 指定快照、独立缓存；不访问其他项目 | 健康恢复与缓存重建，不变更任务状态 |

本地CLI/Desktop必须在Windows实测；可选远程worker单独登记拓扑。不能用WSL成功替代Windows Desktop安装和本地工具生命周期验收。



首次安装检查端口冲突、磁盘空间、路径权限、时间、凭据后端、数据库迁移版本和恢复目录。安装器显示必需依赖及其固定版本；可选 Python/检索组件/模型文件在插件初始化中安装，不由普通研究任务隐式安装到用户全局环境。

## 2. 启停与日常健康

### 2.1 启动次序

1. supervisor 校验被选发行包 hash、签名/来源策略、当前数据格式支持范围、实例锁与 last-known-good 指针。
2. 数据库可用并通过基本一致性检查后，启动控制面；控制面恢复 outbox 和投影水位，进入对账期。
3. Worker 上报本机实例、运行 journal、进程/job 身份、最后事件序号与租约。对账完成之前暂停新派单，保持读取和状态展示可用。
4. 对账后逐渐恢复派单、来源窗口及通知；可选侧车失败只阻塞相应能力。

健康检查区分 `process alive`、数据库就绪、可派单、来源可用、执行器可用与真实端到端成功。根页面返回 200 不代表平台可执行任务；有 key 也不等于 live probe 通过。

### 2.2 停止次序

逻辑 graceful stop 先停止新领取/外部调用，保存周期窗口与游标，再要求 Worker 检查点；可以安全等待的运行继续至配置的宽限期。需要强制停止时记录取消请求、实际停止、未决外部费用与回调，最后刷写 journal/outbox 并停控制面。supervisor 保留。

用户取消一项任务只处理该项及合同指定的未完成依赖，其他项目与已接受成果保留。暂停监控不会删除历史周期或覆盖事实。手机离线不触发取消；电脑睡眠期间界面显示离线时间和最后检查点，不显示持续采集。

## 3. 租约、崩溃和外部副作用恢复

heartbeat 默认 15 秒、租约 90 秒。短失联允许当前动作在租约内运行，禁止超出剩余授权/资源；失效后停止新增调用并回收进程树。控制面重启不凭旧内存继续调度；以数据库与 Worker 对账结果为准。

| 故障 | 恢复动作 | 必须保存的证据 |
|---|---|---|
| 执行进程结束，报告未送达 | Worker 重送同一 run/事件 ID；控制面去重，封存已产物后进入验证 | 退出、产物 hash、运行输入版本、事件序号 |
| 控制面提交成功、响应丢失 | 客户端用原幂等键重试；返回原结果，不生成第二任务 | 原请求 hash、幂等结果与事务提交记录 |
| start 发出、ACK 丢失 | 以 run/幂等键查询 Worker journal；有进程则重连 | 原启动记录、进程/job 身份与租约 |
| Worker 崩溃/主机重启 | 先检查真实进程树与 journal；可证明断开且无未决效果再重建会话 | 重启标识、对账、取消/失联与未知费用 |
| Worker 租约已旧，迟到报告 | 拒绝改变当前 Task；作为迟到观察保存并核账 | 旧 epoch、新归属、拒绝原因 |
| 来源分页处理中断 | 从最后已提交 cursor 重读；内容 hash/来源 ID 去重 | 已提交页、失败页及 source_status |
| 外部写入发出但结果不明 | 查询供应商状态；不能对账则仅阻塞该动作，禁止自动重发 | 请求关联、支持的幂等键、未知效果 |
| outbox 重复/乱序 | inbox 去重、补序号/快照重建投影 | 水位、补取范围、最终投影一致性 |
| 数据库损坏或磁盘写失败 | 停新写入与派单，保存未结进程；使用验证过的恢复包 | 故障范围、最后可用备份、恢复点、受影响任务 |

每次恢复都必须重新核对当前 ContextBundle 与输入版本。若运行器只能重建新会话，则明确记录重建和原始任务身份，不能宣传为原生会话恢复。无法确认旧进程结束时，不将取消标为已完成；无法确认外部请求费用时，不将预留直接按零释放。

## 4. 隔夜、来源窗口与防空转

默认监控周期 6 小时、首次 lookback 7 天；每项目最多一个活动周期；全局执行并发 2、待执行队列 100。来源查询按其实际限流与页大小执行，系统时区存 UTC，用户展示为配置时区，初始 Asia/Shanghai。

电脑重新上线时，将错过触发合并为一个待处理窗口，从最后成功 cursor 续采。某一来源短时积压不生成无限 Task；记录待覆盖时间段并分页补齐。某源失败，其他独立来源继续；覆盖不全保持 `PARTIAL`，不得把“没取到”写成“没有发现”。

有界实验在运行前写定时间、样本、调用/轮数和资源配置；允许数小时与隔夜。模型单次请求、会话窗口或工具超时是执行边界，不自动改变业务 Goal 目标。到达实验边界时保存结果和失败/不确定性，不偷偷增加样本直至出现正结果。

同错误同输入自动重试最多 2 次；临时 429 遵循服务端 Retry-After 与持久化下次尝试时间，避免忙等和进程长睡眠。连续 3 轮无有效新证据或预注册指标改善时转 `DEFERRED_NO_PROGRESS`，保留最好合格版本、计数及恢复条件。计数绑定原始问题/候选/输入 hash，不能借新建子 Goal、换 Agent 或重启清零。

已核验的新来源/上游版本、环境恢复或有效重新规划可以建立有理由的新输入版本；记录与原失败链的关系，防止用无关微小变更绕过熔断。普通“不采用”或“没有改进”是合法完成结果。

## 5. 费用、资源请求和限额变更

### 5.1 费用准入

初始 `UNLIMITED_AMOUNT` 且 cap 为 null，不等于 0，不继承第三方 watchlist 默认金额。仍执行已授权资源范围、并发、队列、重试和实验边界。每次调用保存已知、估算或未知费用；本地运行也记录时间、token/请求和可测资源。

`CAPPED` 同时检查全局、项目、Goal/运行及周期中所有生效约束，不允许子级放宽父级。严格模式在派发前以可靠上界做原子预留；若费用无上界或缺可用定价数据则阻塞该调用，禁止仅用一次历史均价宣称硬限制。各币种分别核算，无明确汇率政策时不隐式换算。

预算账区分已结算、已预留、在途、估算、未知。预留是对在途上界的占用，聚合计算不得把同一笔在途成本再次加算；实际账单晚到时追加对账事件，不覆盖旧观测。供应商无法停止的已发请求可能继续产生费用，界面必须显示该限制。

### 5.2 用户运行中收紧上限

配置变更带 revision 并写审计；立即阻止不能满足新政策的新调用，标记待对账在途请求，按能力请求取消超额运行。不得撤回已发生费用，也不得在修改预算后隐藏原预留。受影响支路 `BLOCKED`，不依赖该资源的工作继续。

资源不足区分鉴权失效、服务限流、额度耗尽、设备容量和工具不可用。只有等价能力、相应用途资格和既有授权均成立的替代路线才能自动切换；模型改变必须更新实际版本与资格检查。

不能自动替换时创建一个去重 ResourceRequest，包含服务/账号引用、原因、已完成事项、可继续支路、所需能力及成本估计/未知。去重按项目、资源类别、账号引用及未解决原因，不反复通知。用户补充资源后重新 probe 并从检查点继续。金额不限不等于系统有权替用户付费、充值或购买新订阅。

## 6. 备份、恢复、导出与保留

### 6.1 备份集合和默认频率

备份至少覆盖权威数据库、不可变对象 manifest/内容、配置与政策版本、adapter lock、发布指针、迁移版本、设备/授权元数据、未决动作索引；密钥仅保存引用及恢复说明，密钥材料另用凭据后端的加密导出能力。没有密钥备份不应阻止可读数据恢复，但须明确对应来源将需重新认证。

工程默认每 6 小时生成一致性备份，升级/迁移前另做一次；保留最近 7 日各次备份与之后 4 个周备份。备份包含敏感项目资料，落在受限路径并加密；用户另配离机目的地后才具备设备丢失恢复能力。同一磁盘第二份不是灾难备份。RPO 目标初始 6 小时，实际恢复时长在演练测量，未测不承诺 RTO。

- SQLite 使用在线备份/快照支持的真实工具，并校验完整性；禁止只复制活跃 `.db` 而忽略 WAL/事务一致性。
- PostgreSQL 使用锁定版本兼容的逻辑或物理备份方式；必须同时覆盖 core 与扩展 namespace。选择方式及命令写入运行清单，不能遗漏插件域。
- 对象采用不可变 hash 文件，备份捕获数据库水位对应的对象 manifest；先保持对象不被 GC，再获取一致性数据库和 manifest，复制所引用内容并逐个校验。备份期间产生的新对象可进入下一次，不可使备份引用缺失对象。

备份记录版本、时间、水位、对象数量/hash、加密方式与校验结果。备份失败不是成功空包；发去重告警并保留上一可用备份。

### 6.2 恢复演练

在空目录/独立数据库恢复，不覆盖活动实例。验证 schema、项目隔离、接受回执 hash、已接受产物、幂等记录、预算未决项、设备授权和事件投影可重建。恢复出的控制面默认禁止外部写与调度，先对账旧 Worker/外部动作，再显式切换实例身份、撤销旧实例写资格后启用。

真实切换时必须阻止旧控制面同时写入或派发，记录切换 epoch。恢复会丢失备份点之后的已提交数据时明确显示损失窗口；不要仅凭任务名称重新发起可能已执行的操作。A12 要求从备份恢复并重复去重/取消/验收关键路径，不是只验证压缩包能解开。

### 6.3 导出和删除

项目导出提供机器可读 JSON、Markdown 摘要、产物与内容 manifest、决定/验收/来源引用及版本说明，排除密钥。导入保留来源身份，但新实例映射项目 ID；外部授权、配对与正在运行的任务不自动启用。

缓存默认可重建；删除/撤销源立即使其检索命中失效。来源留存受访问权限与原始许可约束，不能保存全文时保留可允许的元数据、短引用与未保存说明。正式决定、验收和依赖中的证据按项目保留政策处理，不因日志轮转误删。首版禁止候选自主清理回滚槽、当前备份及被接受成果引用的对象。

## 7. 发布布局、迁移与兼容性

稳定 supervisor 管理至少三个槽：`active`、`candidate`、`last_known_good`。发行包只读、内容 hash 固定；运行数据位于独立目录。使用原子指针/目录切换或经 Windows 实测等效机制，不能覆盖正在加载的二进制；完整路径与脚本由 W02 固定。

Release manifest 记录代码 commit、依赖锁、模型/适配器版本、合同 schema 版本、数据库可读/可写版本范围、升级路径、回滚条件、测试证据及签名/来源校验。W20 必须在干净 Windows 环境复现安装与运行，不能仅从开发机成功推断可分发。

API `/v1` 的增补字段必须保留旧客户端行为；删除/改语义须新主版本或已公布迁移路径。适配器握手声明支持的协议与能力，不支持时具体报错。schema、ContextBundle、来源 JSON 与模型版本升级均以候选验证；使用可变别名时记录实际解析版本，未解析不得继承 Jev 资格。

数据库优先采用 expand → 双版本兼容窗口 → migrate → contract。旧/新程序都能读写同一数据格式时，才允许直接回滚程序指针。破坏性迁移必须先验证备份恢复、回退程序与数据兼容；无法恢复迁移期间写入则设置维护窗口和冻结业务写入，或保留候选暂不发布。禁止承诺任意数据库迁移均可一键无损回滚。

Mu/Pi及Desktop组合升级同时验证共享协议、会话格式、受保护接受门、补丁、打包运行时及Windows路径；升级覆盖验收补丁或破坏双端接续时硬失败。缺口自研同样经过合同与恢复门。依赖锁/SBOM 与许可变化须可核查；候选安装不能替换稳定环境的全局依赖。

## 8. 自主迭代的双流程

项目迭代和系统迭代共享 Evidence/Experiment/Decision/Outcome，但目标分别为 PROJECT 与 SYSTEM。ResearchOS 自身作为受管理项目时，仍由稳定发布控制面监督其代码候选；普通执行 Agent 不取得 supervisor 权限。

### 8.1 知识、提示词、技能和路由

1. 从真实失败、用户纠正、研究发现或性能数据建立 ChangeProposal，说明可测改进与作用范围。
2. 冻结基线版本、留出样例、预注册指标、可接受退化、预算与结束条件。新评分规则本身是另一项改动，不能与候选绑定后自证更高分。
3. 在候选 SkillVersion/配置运行，对账输入覆盖、主张来源、冲突和实际宿主加载。生成文件成功不是学习效果证明。
4. 由未参与生成的样例/验证身份对照稳定版；记录质量、错误采信、人工补述、时间及费用。不具备标签或真实效果时保留 ADVISORY/候选。
5. 通过后在有限、可回退范围试用；观测支持改进才晋升。质量相当但费用降低可以采用；无收益保留稳定版。

既有权限内的常规候选实验可自动运行，无须每步找用户。只有用户独有偏好、缺真实标签/输入或超范围动作才形成明确问题/资源请求。多模型一致不是客观标签的替代。

### 8.2 系统代码候选与独立发布

系统候选使用隔离分支、工作区、进程、凭据及数据库副本，外部动作默认接受控 fixture 或明确授权的测试资源。禁止直接连稳定数据库写入。候选可以提出测试/契约修改，但验证该候选的基线由独立版本保管且不可随候选修改。

发布服务检查：候选 hash 与受测 hash 一致；必需测试/回归/安全边界/迁移/恢复通过；依赖与许可清单完整；没有未决阻断冲突；回滚路径可用；已有授权涵盖本次改变。所有判断以实际回执为证，不用执行者“已跑完”的摘要。

资格通过前只交付隔离候选和发布演练。A16 证明稳定 supervisor 可在候选启动失败、健康退化、错误采信、进程挂死及回滚过程中独立工作后，才开放所覆盖范围的自动晋升。模型权重训练不在首版范围。

## 9. Canary 与回滚的具体默认

首版采用**串行有限项目 canary**，不启动第二个竞争主数据库的业务调度器：

1. 候选先在数据库/对象快照的隔离副本完成 replay、回归、迁移和启动演练；回放外部效果被禁止或使用明确测试资源。
2. 通过独立发布门后，稳定控制面停止新领取并排空或检查点在途运行。创建升级备份，验证 last-known-good，再由 supervisor 切换唯一活动控制面。
3. 新控制面 canary 期间仅允许白名单 ResearchOS 自身项目的一个真实研究周期和规定只读来源/受限实验；其他项目读取可用但暂缓新派单。已有不允许中断的任务未安全处理前不能切换。
4. 初始观测窗为至少 1 个完整周期且不少于 6 小时；最长 24 小时未完成必需观察则暂停扩大范围，保持“待证明”或回滚。设定要求来源真实可用，fixture 不计作完整 live canary。
5. 由独立监督与验证检查无关键错误采信、无跨项目泄露、无漏验收放行、无丢失/重复外部效果、可恢复且预算符合政策。性能/成本依据预注册比较区间，不用“感觉更快”判断。
6. 通过后更新稳定指针并逐步恢复其他项目派单；失败时停新派单、保存故障与未决效果、回到 last-known-good 并对账，再重开可执行支路。

这只是唯一实例的部署 canary；候选隔离测试可并行，但不能在共享生产真值上并行抢单。若未来需要多实例流量 canary，另建带 fencing 和分区所有权的变更提案，不在首版偷加第二调度层。

自动回滚触发包括：无法按规定时间就绪、稳定关键健康检查连续失败、必需状态不变量被破坏、实测错误采信/回归、凭据越界、候选违反预算或资源准入政策。供应商欠费/限流等与候选无因果关系的资源事件按资源请求处理，不靠循环切版本解决。就绪检查工程默认 120 秒，稳定健康连续 3 次失败且持续至少 30 秒触发；数据库迁移期间按事先冻结的窗口单独判断，不能用运行时临时延长绕过失败。

回滚不得依赖坏掉的新控制面自救。supervisor 先撤销新派单权限并处理 Worker，判断数据库是否仍兼容旧版；兼容则切程序指针，不兼容则执行演练过的维护窗口恢复。若无法安全回退，停止写入并进入恢复状态，不启动旧程序破坏新格式。失败候选被冻结，只有新证据/修复及新版本可重试，防止循环升降。

## 10. 设备配对、远程监督与撤销

Windows 执行、手机监督。电脑本机首次设置为 Owner；远程默认关闭。开启时选择经资格验证的 TLS 入口，公开地址只指向控制面受鉴权路由，不暴露数据库、Worker、CLI、检索服务或未加固上游管理端。

桌面生成至少 128 bit 随机一次性配对令牌，默认 5 分钟过期、一次消费，二维码不包含主账号密钥。手机持有独立设备凭据，服务端保存不可逆验证材料与设备 scopes；默认只读，控制能力由现有授权显式授予。cookie 采用适当的 HttpOnly/Secure/SameSite，跨站请求、Origin 与 CSRF 控制须实测，不能只隐藏按钮。

撤销设备后下一认证请求立即被拒，敏感写每次校验撤销状态，现有事件流与刷新凭据失效；服务在 30 秒内主动关闭对应事件会话，不等旧连接无限存活。手机丢失不要求重新建立全部项目，也不停止电脑已有合法任务。变更 Owner、配对、新设备权限和远程入口写审计，但日志不含令牌或 cookie。

390px 手机抽屉与 1440px 桌面侧栏显示同一 ProjectState：阶段、已验收/当前计划计数、待评审、阻塞、最后有效进展及最近成果。离线页面标明缓存时间；重连按快照水位和增量补取，不重发旧控制动作。在服务、网络与凭据恢复可用后 120 秒内完成状态对账。前端失联不把后端运行误标取消或成功。

## 11. 可观测性与重大成果

结构化日志带 project/task/run/correlation ID、组件和版本、事件序号、耗时及结果分类。默认不记录完整凭据、请求鉴权头或任意私有源全文；确需诊断的原始内容作为受权限保护的 Artifact 单独保存。日志默认保留 30 天并轮转，正式证据与验收依项目保留政策另存。

监控至少包括：活动/待处理/阻塞任务数、队列等待、最后有效进展、租约失效、未决取消、未结外部效果、来源覆盖和延迟、outbox积压、投影落后、费用类别、资源请求、备份年龄、发布与回滚状态。token 速度只是遥测，不能推导完成百分比。

MilestoneRelease 按项目单调序号，软件 semver 另记。通过验收的功能/实验、关键采用或排除、推翻旧决定、系统晋升和重大回退可构成成果；普通抓取、模型消息、草稿与重试仅入活动流。默认应用内通知，外部发送需要实际渠道与授权；“版本 push”不自动执行 Git push。

周期结束报告至少包含：来源范围与缺口、候选处置、已验证结论、实验结果、未决项、已采取动作和下次复查。简洁模式保留部分失败与不确定性，完整回执可展开。同一 release 对同一用户/渠道逻辑通知一次，重投和手机离线补看不重复制造新成果。

## 13. 评测引擎与UI运行补充

评测引擎版本、lockfile、配置、数据集、候选和rubric纳入恢复/发行manifest。正式留出与明细存储跟随受限备份策略，候选工作目录不含可读备份。恢复后先校验ACL、身份与出站规则，再放行资格评测；不能恢复成默认公开目录。

断线时工作台显示最后同步时间和可能过期状态；电脑休眠不显示仍在采集。重连以项目水位对账，乱序/重复事件不会重复发布通知。重大成果通知引用不可变MilestoneRelease，普通步骤留活动流。

版本升级比较同一冻结基线；更换模型/adapter/rubric导致资格范围失效时降级并重验。Promptfoo的合格报告、Jev资格与系统发布批准分别记录，W16仍依赖W18恢复验证及真实canary/回滚。

## 11. CLI/Desktop生命周期

窗口关闭、缩到托盘、CLI detach与显式退出按14/设置分别处理；只有真实持久宿主存在才显示后台执行。每次重开先握手同一核心版本与会话owner，再补事件。人工停止不会被另一入口自动恢复；取消清队列并核验子进程。备份同时覆盖会话日志/域映射和不可变产物，升级回退验证两个客户端与存储兼容。
