# ResearchOS 产品需求规格 v2.0

日期：2026-09-30（Asia/Shanghai）  
效力：实施规格；与本包数据、接口、WBS、验收合同共同生效。  
产品验证状态：`NOT_RUN`。本文件定义待实现行为，不表示已开发、已集成或已完成 Windows 实机验证。

## 1. 产品目标与首条交付主线

ResearchOS 是单用户的 AI 研究与执行工作台。用户提出想法后，系统形成目标、维护共享背景、组织 Agent 工作、验证成果，并根据可观察结果改进所管理项目和自身工作方法。

**首条必须交付的主线：持续跟踪 GitHub、X 和论文，找到与当前项目问题有关的线索，核验一手证据，开展有界实验，形成有依据的采用、拒绝、观察或暂不能判断结论。** 研究结果必须回到项目的下一步；资料数量、Agent 数量和报告长度不作为完成标准。

首个受管理项目默认是 **ResearchOS 自身**，上下文来自本实施包和实施时建立的隔离仓库。系统以本包中的“跨会话连续性、证据可靠性、冲突处理与执行成本”为首批研究主题，选择一个已登记问题完成真实研究闭环。用户无需另外整理技术表或先提供旧项目。其他项目经明确导入后才进入管理范围；不自动读取 Quill Club、xiaoshuo 的文件、连接器、账户或历史状态。

用户的长期期待是：一个想法可以持续推进，并在真正需要业务选择或补充资源时才找用户。首版通过下面的有限、可验收能力实现这一期待，不以“保证永远变好”作为承诺。

## 3. 使用者、边界与产品范围

### 3.1 使用者和职责

- **Founder：**提出目标、调整优先级和权限、处理只有本人能确定的业务偏好、补充确实缺失的资源；可暂停、恢复、取消任务并查看证据。
- **规划与研究 Agent：**读取共享背景，提出候选、反证、实验和任务计划；事实与假设分开登记。
- **执行 Agent：**在分配的范围内调用工具、产出文件和运行回执；不能仅凭自己的完成声明接受任务。
- **独立验证者与程序验证器：**检查冻结条件、实际产物、原始证据与版本一致性；按合同提交可追溯回执。
- **ResearchOS 宿主：**维护状态、身份、权限、费用、消息、任务调度和验收提交；Agent 的意见不能越过宿主检查。

“独立验证”首先指执行身份与验收权限分离、检查实际产物；更换模型名字本身不构成独立验证，也不自动保证结论正确。首版至少有一个真实可调用的执行器，不要求用户现有所有品牌终端同时接通。

### 3.2 首版范围

| 必须纳入 v2.0 | 可选或后置 |
|---|---|
| 想法转 Goal、ResearchOS 项目初始化、显式资料导入 | 自动接管未导入的旧项目 |
| 共享项目状态、跨会话交接、版本冲突和影响传播 | 无限制理解所有自然语言隐含依赖的承诺 |
| GitHub、X、论文实际来源接入与完整研究闭环 | 全网无遗漏监控、绕过付费/登录/限流限制 |
| 基线、预注册实验、独立验收、负结果与反证 | 强制产生采用成果或预设性能改善百分比 |
| Jev 实际调用、用途资格评测、弃权与降级 | 未通过资格的用途自动决策；只靠模型评分通过验收 |
| 一个真实执行器、隔夜运行、断点恢复、预算和资源请求 | 同时适配所有 CLI、所有桌面端和所有模型 |
| 桌面工作台、手机监督、重大成果记录和通知 | 原生手机 App、手机承担长任务运算、办公室动画 |
| 候选知识/技能的生成与评测、系统代码隔离候选与回退 | 基础模型权重训练；候选自主修改自身晋升门槛 |
| 项目隔离、设备配对、密钥管理、备份和恢复 | 商业多租户、公开插件市场、无人约束的采购付款 |

本包将完整 v2.0 分阶段实施，阶段交付不能替代完整范围。前期固定样例可验证协议；完整产品关闭必须取得真实来源、实际 Jev 调用、Windows 隔夜和恢复回执。个别 Jev 用途未获得自动化资格时可维持 advisory，不能把这种限制隐去。外部服务资源不足只阻塞相关门，合同实现和其他独立分支继续。

### 3.3 自主推进和找用户的边界

已有目标与授权覆盖的读取、资料整理、任务拆分、可逆实验、有限修复和评审自动推进。普通技术选择采用本包默认，不逐项请用户批准。

以下情况形成具体、去重的请求：存在会导致不同业务方向且上下文无法解决的偏好；所需动作确实超出当前授权；没有合格替代路线的账户、额度、密钥或设备资源不足。请求必须带原因、已经完成的工作、受影响任务、可以继续的部分和恢复条件。请求出现时只阻塞受影响分支。资金模式不限并不授予代为购买、充值、签约或对外发消息的额外权限。

## 4. 需求合同

所有 R01–R20 为 v2.0 的 **Must**。条目内标明的 **Should** 是可以降级且必须披露的增强项；“后置”不进入 v2.0 关闭门。测试场景的操作步骤和固定断言由 `06_ACCEPTANCE_TESTS.md` 及 `contracts/acceptance.json` 定义，下列引用只建立追踪关系。

### R01 想法转为可执行目标

- **用户行为：**用自然语言给出想法，补充或修订业务方向；无需填写架构、测试命令和数据字段。
- **系统行为：**形成版本化 GoalBrief，保存原始意图、问题、范围、产物、依赖、验收条件、资源策略和失败出口；区分 `USER_STATED`、`OBSERVED`、`ASSUMED`、`PROPOSED`。依据当前 ProjectState 拆任务并登记依赖。
- **成功边界：**已知信息足够时可直接进入计划；每个执行任务具有可检查的产物和完成条件；目标实质变化留新版本及理由。
- **失败边界：**不能把 AI 建议转写成用户要求，不能通过删减失败条件宣布完成；缺少关键业务方向时准确请求决策，不能任意替用户选择。
- **优先级与映射：**Must；W00、W04、W06；C01、C20、A01、A03。

### R02 项目背景与资料导入

- **用户行为：**首次使用接受默认 ResearchOS 项目；可选择资料或明确指定其他项目导入范围。
- **系统行为：**从授权材料提取项目目标、阶段、约束、当前方案、未完成事项及历史决定，生成 ProjectProfile；保留来源和导入清单，将相互矛盾内容登记为未决项。
- **成功边界：**首个项目不依赖旧 Quill Club 资料即可建立；每份期望输入都有成功、失败或排除原因；重复导入不重复产生有效事实。
- **失败边界：**未知内容不补写成事实；部分解析失败不能因批处理退出正常而声称导入完成；不扫描未授权目录或自动混入其他项目资料。
- **优先级与映射：**Must；Should 支持更多文档格式，首版合同及其真实可用格式必须明示；W00、W04；C01、C02、A01、A06。

### R03 共享上下文与跨会话恢复

- **用户行为：**更换 Agent、关闭会话或隔天回来时直接继续任务，不重新粘贴已保存背景和产物。
- **系统行为：**维护唯一 ProjectState，给每次任务生成带版本向量和 hash 的 ContextBundle，包含必要事实、未决事项、废弃决定、最新产物和原始记录引用。新会话先核对状态与检查点。
- **成功边界：**接手者能够恢复同一任务的当前目标、有效决定与下一步，摘要可追溯原文；未完成承诺不会因摘要压缩消失。
- **失败边界：**聊天摘要或 Agent 私有记忆不能覆盖项目权威状态；无法证明当前版本时先同步或阻塞相关写入，不使用旧背景提交正式成果。
- **优先级与映射：**Must；W04、W06、W12；C01、C11、C13、A03、A14。

### R04 变更影响与冲突处理

- **用户行为：**修改需求，或查看系统发现的前后矛盾；用户无需逐文件转发变更。
- **系统行为：**用有类型依赖定位影响对象，生成 ChangeProposal 和整合任务；相关任务置 `NEEDS_REVALIDATION`，相关产物失效，无关任务继续。并行写入带期望版本；冲突返回明确结果并保存双方内容。
- **成功边界：**相同输入与依赖可重现影响分析；两个冲突提案最终只有一个被接受的生效结果；提交时再次检查输入和产物版本。
- **失败边界：**旧版本提交不得覆盖新版本；不能自动以最后写入获胜吞掉他人修改；语义冲突检测结果只能作为提示，不能宣称覆盖所有隐含关系。
- **优先级与映射：**Must；W03、W04、W06；C03、C04、A03、A06。

### R05 GitHub、X 与论文持续研究

- **用户行为：**启动、暂停或调整项目研究主题，查看与当前问题有关的研究结果。
- **系统行为：**按来源游标增量采集；将候选关联未解决问题和历史尝试；执行去重、核验、实验、评审、交付和跟踪。长期监控与有完成条件的单轮 ResearchCycle 分开保存。
- **成功边界：**本轮必需来源与实验全部完成、处置和游标已保存时为 `COMPLETE`；`ADOPT`、`REJECT`、`WATCH`、`INCONCLUSIVE` 都可以是合法结论；没有值得采用的候选也能正常结束。
- **失败边界：**X 未配置或限流时继续其他来源，但本轮不能称完整覆盖；有实质结果但缺必需来源/实验为 `PARTIAL`，无法实质推进为 `BLOCKED`；未经验收的候选不能直接修改项目。
- **优先级与映射：**Must；W07、W08、W14；C05、C06、C11、A05、A13。

### R06 证据来源、去重与覆盖

- **用户行为：**展开结论，查看来源、时间、引用位置、版本、反证和来源缺口。
- **系统行为：**保存原始发布者、上游传播关系、抓取时间、原文快照和 hash；区分 `OBSERVED`、`SIMULATED`、`GENERATED`。证据有效性单独标记 `CURRENT`、`STALE`、`REVOKED`；引用必须能定位到冻结来源。
- **成功边界：**关键主张有可核验支持或明确的不确定标记；转载不增加独立证据数量；来源失效或授权撤回会影响下游有效性。
- **失败边界：**X 转述不能未经核实当一手结论；模型回答、模拟人物发言和不同模型一致不能伪装成独立现实证据；来源访问失败不能替换为模型记忆并保留“已核实”标签。
- **优先级与映射：**Must；Should 增强语义检索，基础检索必须独立可用；W07、W09；C06、C19、A05、A06。

### R07 有界、预注册实验

- **用户行为：**查看候选为何值得实验、与什么基线比较、投入多少资源及结果意味着什么。
- **系统行为：**在执行前冻结假设、输入、基线、成功/失败/无结论条件、指标计算、停止条件、允许变更范围和回滚路径；真实运行后保存原始回执、环境和产物版本。
- **成功边界：**另一执行者能依据记录复现实验；负结果与无结论照实入账；实验与后续采用是不同状态，后者还需验收和授权。
- **失败边界：**不能看完结果再改变门槛、移除失败用例或把未执行项视为通过；没有基线不能声称改善；需要实验但资源不足时保留阻塞，不靠高评分跳过。
- **优先级与映射：**Must；W10、W14；C05、C07、C20、A07、A13。

### R08 Jev 按用途取得判断资格

- **用户行为：**看到 Jev 的判断、作用范围和当前自主等级；不用逐次替系统完成普通定性评审。
- **系统行为：**按“任务类型 × 语言 × provider × 模型版本 × rubric 版本”维护 `SHADOW`、`ADVISORY`、`BOUNDED_AUTO` 资格；真实调用记录模型及规则版本。信息缺失、低置信或矛盾由宿主标为 `ABSTAIN`，自动补证、重评或观察。
- **成功边界：**通过预注册资格的用途可在已有授权内自动判断；中文和中英混合按独立样例校准；Jev 不可用时基础状态、检索与合格替代流程仍可工作。
- **失败边界：**用途资格不能互相借用；模型更新不能沿用旧自动化资格；概率不能表述为真实世界成功率；真实 Jev 调用与其他模型模拟不得混记。资格失败可维持 advisory，但必须披露且验证回退。
- **优先级与映射：**Must 的是实际调用、资格机制和降级；未取得资格的 `BOUNDED_AUTO` 为后续晋升，不是默认开关；W11；C07、C08、A08、A13。

### R09 独立验收与完成判定

- **用户行为：**查看已验收成果及其证据，能区分执行结束、待评审和真正完成。
- **系统行为：**将任务执行报告送入 `VERIFYING`；组合强制程序检查、必要的独立评审、合格 model rubric、当前输入/产物版本一致性和未决冲突检查，生成不可覆盖的验收回执，再由宿主提交 `ACCEPTED`。
- **成功边界：**“完成”依据冻结合同及实际产物；必要的定性判断可由已校准评审承担，不普遍要求用户逐项审批；验收与引用产物 hash 绑定。
- **失败边界：**执行者不能接受自己的任务、修改自己的必需验收门或以 Jev 高分覆盖测试失败；运行结束、进程退出 0、报告完整均不足以单独宣告验收通过。
- **优先级与映射：**Must；W06、W10、W11；C07、C10、C20、A03、A07、A08。

### R10 执行器、派单与协作

- **用户行为：**给出目标后让系统在可用能力之间派单；必要时查看谁在做什么及交接情况。
- **系统行为：**登记真实可用执行能力，给任务绑定执行实例、隔离工作区、工具权限和上下文；保存 Agent 消息、回执和交接确认，重复消息去重。只能有一个负责业务任务推进的调度权威。
- **成功边界：**首版至少一个真实执行器完成从派单到独立验收；能力暂缺显示未分配；取消同时处理排队请求与运行进程，报告无法立即终止的外部动作。
- **失败边界：**UI 动画、模拟 Agent 或会话结束信号不能冒充真实执行；插件内部日程不能另建业务调度真值；不因有模型名称就声称对应账户可用。
- **优先级与映射：**Must；Should 逐步接更多执行器；W01、W05、W06；C04、C11、A02、A04。

### R11 费用与资源不足处理

- **用户行为：**初始不填金额即可运行；随时设上限或收紧范围；收到明确资源请求后补充资源。
- **系统行为：**区分 `UNLIMITED_AMOUNT` 和 `CAPPED`；遵从所有适用层级中最严格限制；分别记录已花、预留、在途、估计和未知费用。严格限制要求可靠费用上界和并发预留，未知费用无法满足严格限制时阻塞相关调用。
- **成功边界：**不设限时不因金额空值阻塞；上限生效后停止新的不合规调用；合格且授权的替代路线可继续，否则创建去重 ResourceRequest，补充后从检查点恢复。
- **失败边界：**`null` 不能变成零上限；未知不能记为免费；不能隐式换汇、抹掉在途费用或宣称停止就消除了已发出请求的费用；替代路线不能降低必需验收标准。
- **优先级与映射：**Must；W12；C13、C14、C15、A03、A14。

### R12 持久运行、恢复与防空转

- **用户行为：**允许任务跑数小时或隔夜；关闭手机或模型窗口后仍能查看电脑上的真实运行状态。
- **系统行为：**保存任务身份、来源游标、检查点、幂等键和恢复条件；断网或重启后对账已有结果，再续跑未完成动作；按本包默认限制重试、并发、队列和无进展迭代。
- **成功边界：**电脑与必要服务正常时可跨会话持续；重启不重复副作用；错过周期合并为有限补采窗口；连续无进展转 `DEFERRED_NO_PROGRESS` 并保留最好合格版本。
- **失败边界：**电脑休眠、断电、未配后台运行时不能显示持续扫描；不能通过新建子 Goal 重置失败/无进展计数；延期不能伪装成验收通过，取消不能只关闭展示界面。
- **优先级与映射：**Must；W12、W19；C11、C13、C16、A04、A14。

### R13 阶段侧栏与真实进度

- **用户行为：**桌面查看常驻侧栏，手机展开抽屉，随时了解当前阶段、阻塞、最近产物并执行有限控制。
- **系统行为：**从真实事件投影“发现、核验、实验、评审、交付、跟踪”；展示已验收数、当前计划数、待评审、阻塞和最后有效进展；计划修订显示变化。
- **成功边界：**侧栏与任务账本、成果记录一致；不同候选可同时位于不同阶段；断线重连补齐快照和缺失事件。
- **失败边界：**不另存一份手工进度真值；待评审不计已完成；没有固定可靠分母时不显示总体百分比；重连不能把旧事件重放成新成果。
- **优先级与映射：**Must；W13；C17、C18、A10、A13。

### R14 重大成果版本与通知

- **用户行为：**重大成果出现时收到简洁汇报，点开可看变化、证据、未决点和下一步。
- **系统行为：**通过验收的新功能/实验、关键采用或拒绝、推翻旧结论的证据、系统晋升及重大回退形成 MilestoneRelease。相关变化合并；普通抓取、草稿、重试留活动流。成果与通知 outbox 同事务提交并去重。
- **成功边界：**每项目成果序号单调增加；通知与侧栏指向相同成果和验收版本；手机离线后能补看，重复投递只有一条逻辑通知。
- **失败边界：**未验收草稿不能称重大交付；成果修正通过新记录替代，不覆盖历史；“像版本 push”不自动授权 Git push、部署或外部消息发送。
- **优先级与映射：**Must；外部渠道 Should，首版默认应用内；W13；C17、C18、A03、A10。

### R15 知识、技能与策略迭代

- **用户行为：**不再人工持续投喂工具清单；查看系统从研究与失败中沉淀了什么、为何启用新方法。
- **系统行为：**把核验资料和经验生成带来源的候选知识、技能、检索/排序/路由策略；与当前稳定版本比较，通过固定样例及必要的真实任务评测后晋升，保留旧版本和撤销条件。
- **成功边界：**候选与正式启用分开；资料批次覆盖可核对；负结果保留，未来相同问题能找回。借用组件自带上下文文件时从 ProjectState 导出，写回作为提案处理。
- **失败边界：**生成 SKILL.md 或安装成功不等于能力可靠；抽取漏文档不得隐瞒；模型分数变高不能单独证明系统变好；不得自动信任外部技能内嵌指令或给其新增权限。
- **优先级与映射：**Must；更多技能生成工具及营销/模拟能力后置；W15；C01、C12、C20、A06、A09。

### R16 系统自身代码迭代与回退

- **用户行为：**允许系统在授权范围内持续改善工作方法和自身实现，查看候选的效果与回退记录。
- **系统行为：**将系统代码变更放入隔离候选，冻结评价基线，进行回归和小范围试用；稳定监督与发布控制独立于候选进程，验证版本、迁移和恢复能力后才能晋升。
- **成功边界：**候选有效则可在既有授权内晋升；出现回归或采用效果恶化时恢复已接受版本并冻结候选；即使候选无法启动，稳定恢复控制仍能工作。
- **失败边界：**候选不能修改自己的验收标签、放宽必需测试、扩权或替换批准自己的控制面；不可逆迁移不能伪称普通自动热更新；基础模型权重训练不在本需求内。
- **优先级与映射：**Must 的是隔离候选、独立验证和实测回退；自动晋升仅在对应发布资格已取得后启用；W16；C09、C10、C12、C20、A16。

### R17 项目隔离、权限、设备与密钥

- **用户行为：**明确导入项目、配对监督设备、设置可用资源并可撤销访问。
- **系统行为：**对每次状态读取、工具调用和路径访问核对项目、任务、身份和授权范围；向 Agent 提供必要引用，密钥由受控凭据层注入，日志和导出脱敏。手机访问经过身份验证和设备配对，撤销后拒绝继续访问。
- **成功边界：**同名项目材料不会混用；共享通用知识有显式范围；远程监督与执行权限分开；外部技能/网页内容不能改变宿主权限。
- **失败边界：**不能依赖模型自觉保密代替程序限制；不可将任意宿主路径直接暴露为远程读取参数；未取得远程访问资格时不得自动向公网开放服务。
- **优先级与映射：**Must；W04、W05、W17；C02、C10、A01、A06、A11。

### R18 备份、导出与恢复

- **用户行为：**导出项目及成果、恢复备份，在故障后取回已接受成果和未完成工作。
- **系统行为：**备份状态、产物、校验信息和必要版本元数据；导出资料保留关系与来源，密钥单独受控处理；在隔离目标验证恢复和迁移。
- **成功边界：**能够校验并还原项目当前版本、任务、证据、验收、费用状态和待处理通知；恢复后进行对账，避免重复执行副作用；可说明恢复点及未覆盖时间范围。
- **失败边界：**“写出备份文件”不等于恢复通过；损坏、缺少产物、密钥不可用或迁移不兼容必须显式失败；不得静默覆盖唯一有效数据。
- **优先级与映射：**Must；W18、W19；C11、C13、A12、A14、A15。

### R19 桌面与手机可用性

- **用户行为：**在 Windows 电脑启动工作台、配置资源并查看产物；在手机查看阶段、阻塞、费用、证据，暂停、恢复、取消或调整已开放配置。
- **系统行为：**提供响应式界面、明确状态与错误、可聚焦和可键盘操作的控件、可展开的证据；显示连接与最后同步时间，控制动作返回实际生效结果。
- **成功边界：**Windows 实机可安装/启动/退出/重开；手机常用视口完成监督流程；屏幕窄时内容和关键操作可读可达；网络恢复后状态一致。
- **失败边界：**手机按钮反馈不能代替服务端确认；不能把 Linux 固定样例测试当作 Windows 通过；设备离线时不能显示未经确认的最新执行状态。
- **优先级与映射：**Must；原生 App 和手机执行后置；W13、W17、W19；C17、C18、A10、A11、A14。

### R20 审计、基线指标与可复现交付

- **用户行为：**查看一个结论如何得到、系统是否减少了交接负担，以及这一版本究竟验证了什么。
- **系统行为：**按 project/goal/task/run/correlation ID 连接事件、模型调用、实验、费用、产物和验收；保存命令、锁定依赖、环境及实际测试回执；按下文指标先测基线，再比较同类任务。
- **成功边界：**可以从成果回溯到输入和证据；打包交付能按文档重建并运行实际已验证命令；真实测试、fixture、mock、未运行结果清晰分开。
- **失败边界：**不以仓库 README、作者实验或模型自评替代本产品验证；不能把未运行项写为通过；不在没有同条件对照时填写改善幅度。
- **优先级与映射：**Must；W02、W20、W21；C19、C20、A13、A15、A16。

## 5. 首次使用到持续运行的用户流程

1. **初始化。** 用户启动桌面服务，系统从本实施包建立 ResearchOS 项目、展示默认运行策略和当前可用能力；不要求填技术方案。缺失账户形成明确配置/资源请求。
2. **接续目标。** 用户可以直接提出想法，或采用本包登记的首批研究主题。系统读取已有背景，生成 Goal 和任务，展示已确定内容、必要假设和真正未决的业务选择。
3. **研究推进。** 系统按照近 7 天首次窗口和项目问题查询三个来源；侧栏逐步显示候选、覆盖、核验和实验，普通过程无需用户盯着。
4. **验证交付。** 实验前冻结比较条件；实际执行后独立评审，形成采用/拒绝/观察/无结论。重大结果形成成果版本；采用建议进入实施仍须满足任务授权和验收。
5. **持续跟踪。** 监控按 6 小时默认窗口继续；有新证据或采用反馈时生成变更任务，影响当前结论时传播失效；避免重复相同无进展实验。
6. **离开与回来。** 用户手机离线或模型会话关闭不改变任务身份；重连看到真实状态。电脑中断时系统从检查点恢复并显示中断时间，不能声称期间仍在扫描。
7. **沉淀与自身改进。** 合格经验进入知识与技能候选；系统代码改进在隔离环境验证。任何晋升都能解释因何发生，任何退化都能回到可用版本。

普通看板以“正在做什么、为何做、已验证什么、还差什么”组织信息。默认摘要短而可展开，不要求用户阅读原始 Agent 聊天才能判断成果。

## 6. 完成层级与产品关闭条件

| 对象 | 可声明完成的依据 | 不能替代完成的信号 |
|---|---|---|
| 一次工具/模型调用 | 协议结果与调用回执完整 | HTTP 成功不等于研究结论正确 |
| 一个任务 | 当前输入和产物版本通过冻结验收，宿主接受 | 执行者说完成、进程退出、报告写完 |
| 一轮研究 | 必需来源与实验完成，结论/后续/游标落库 | 只有两个来源成功、缺必需实验、强行凑采用项 |
| 一个成果版本 | 关联变化经有效验收并形成不可变记录 | 普通抓取、重复事件或草稿生成 |
| 一次系统改进 | 隔离评测与回归通过，试用及恢复资格满足 | 换评分规则后高分、改动数量更多 |
| v2.0 产品 | 本包 Must 的合同和真实门通过，材料可重现 | 固定样例全绿但真实来源/Jev/Windows/隔夜未运行 |

监控服务可以持续存在；关闭一个已满足条件的 Goal 不关闭用户仍启用的长期监控。反过来，长期监控仍在运行也不能阻止已经完成的单轮研究交付。

完整发布至少包含 A13 真实三来源闭环、实际 Jev 调用与 A08 资格结论、A14 Windows 隔夜/恢复、A12 备份恢复、A16 候选代码失败回退和 A15 可复现交付。具体门以验收文件为准；本 PRD 不把缺少外部资源重命名为“通过”。真实来源查询结果为空可以是有效结果，来源根本未成功访问则不是完整覆盖。

## 7. 成功指标与首轮测量

先建立基线，再决定改善目标。每次比较冻结任务范围、输入、模型版本、来源覆盖与环境，记录样本量和缺失项；不能把不同难度和不同范围的任务直接混算。

| 用户关切 | 首轮记录的指标 | 解读边界 |
|---|---|---|
| 不想重复交接 | 已具备输入的任务中，用户重复提供既有背景/产物的次数、耗时及原因 | 系统确实缺失的新业务信息单独统计 |
| 不知道结果可靠 | 关键主张的可核查证据覆盖、独立抽查错误采信、缺口正确保留情况 | 覆盖率高不等于结论必然真实 |
| 前后工作冲突 | 旧版本错误晋升次数、已登记影响对象检出、无关任务误阻塞、冲突丢失次数 | 隐含语义依赖另记，不能宣称完全检测 |
| 研究能否落地 | 候选到实验/结论的耗时、实验结果、采用后观测、拒绝/观察理由 | 不强制采用率，不因合理拒绝而扣作失败 |
| Jev 是否有价值 | 分用途错误采信、错误拒绝、弃权、延迟、费用及确定性基线对照 | 多模型一致不是正确标签；按资格集与 holdout 分开报告 |
| 自我迭代是否有用 | 同条件任务质量、回归、用户介入、时间和费用，以及稳定期反馈 | 只有评分规则变化不算改善；负结果保留 |
| 长任务是否可靠 | 重启恢复结果、重复副作用、恢复耗时、最后检查点与实际中断 | 实机和真实运行回执独立于 fixture 统计 |

W21 输出首轮基线与观察结论。**当前值均未测量**，不得预填“节省百分比”“成功率提升”或“已达到自治”。确有进步时才能据可复现实验提出下一轮目标；无提升时保留稳定方案。

## 8. 交付与变更约束

本 PRD 的要求编号 R01–R20 保持稳定，WBS、数据/API、验收与实际回执引用这些编号。对需求范围、验收门槛或自主权限的修改，必须以变更提案说明原因和受影响文件，再作为新版本生效；不得由执行 Agent 局部改一份文档来降低当前任务难度。

已调研组件进入候选登记。实施时先完成 W01 底座路线资格，并由 W02 产生在所选路线实际验证的运行命令和依赖锁定；任何调研建议都不能跳过这两个任务直接变成已选依赖。数据与接口的精确字段、状态和错误语义在合同文件中定义；发现跨文档矛盾时暂停受影响写入、提出修订并同步合同，不自行猜测另一套字段。

本包完成意味着 AI 已取得一套可执行、可追踪、可验收的产品合同；产品本身是否完成，只由后续真实实现与验收回执决定。
