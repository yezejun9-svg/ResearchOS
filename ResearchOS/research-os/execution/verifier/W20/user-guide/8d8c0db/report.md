## 权限与含义边界

OpenAPI 操作角色与 HTTP 认证/项目范围检查相符（`internal/domain/http.go:112` 起）。原始想法额外要求当前项目 Owner，确认时核对原提交者（`intent_planning.go:14,50`）。背景候选流程的 `sealArtifact` 额外角色要求被明确写出，单一 Owner 不能被承诺完成整条表单。设备权限保持当前授权项目范围，与本机管理能力分开（`remote_auth.go:19` 起）。指南未给出新签发令牌、解除激活限制、修改身份或绕过拒绝的指令。

任务使用 `EXECUTION_REPORTED`、`VERIFYING`、`ACCEPTED`；`RUN_RESULT` 被明确限定为交接用语而非当前页面状态。规划 ACCEPTED 不等于业务目标完成。`SETTLED` 仅是运行收尾，`CANCEL_REQUESTED` 不等于执行器已取消。来源未配置、限流或失败与持久化零记录分开；`money=null`、`UNKNOWN` 不被替换为金额 0。

预览与下载均经过服务权限及当前产物检查（`http.go:619`）和前端哈希核验（`preview.jsx:19,41`）。背景编辑保留本地草稿与冲突双方，候选提交不等于已应用修订；页面状态草稿和工作台 localStorage 原始想法的寿命区别说明准确。

普通请求 30 秒超时、SSE 静默看门狗、恢复快照、业务数据 lastSync 与心跳分离可在 `api.js`、`hooks.js` 确认。指南正确限定统一 mutate 入口才有已同步后断线拦截，其他表单可能请求失败；没有承诺通用离线队列或自动重发写入。双主题、767px 及以下布局和抽屉键盘行为与 `main.jsx`、`style.css` 一致。这是实现说明，不是新做的浏览器/可访问性验收。
