5: ## Trust and two finite build phases
6: 
7: A caller-supplied plan hash is integrity, not approval. Choose one operation-specific dedicated executable whose private link-time grant pins externally accepted inputs. No signing program, signing key, registry, environment override, runtime grant file, force flag, test bypass or caller callback is introduced. Trust is the declared same-SID Owner/operator review/build workflow and pinned build output, not protected holdout or resistance to a malicious same-user administrator rebuilding arbitrary code.
8: 
9: Preflight creates backup and a final plan; final plan bytes cannot be approved before they exist. Resolve that dependency explicitly with two builds of the same accepted Source:
10: 
11: 1. **PREFLIGHT_ONLY build** contains a nonempty grant for one exact canonical preflight subject/proposal document, its independent preflight review, public evidence manifest and Root preflight scope. It can run only that proposal's real preflight and inspect its own results. It has zero terminate authority. Preflight output includes the canonical final plan, backup manifest/census and a complete immutable evidence manifest.
12: 2. Root and an independent reviewer inspect those actual preflight outputs. Only a later authorized **STOP_ONCE build** contains the final plan SHA, complete preflight evidence manifest SHA, independent stop acceptance/review SHA and Root actual-stop scope SHA. It can run commit for precisely that operation and inspect that journal; it cannot refresh a plan/backup or run another preflight. It is a new build artifact, not a mutation of the already pinned preflight binary.
13: 
14: The two grants have different build identities and grant digests, share operation ID and exact subject, and the STOP_ONCE grant includes the preflight grant digest and preflight executable digest. No hash cycle: preflight proposal SHA excludes measured outputs; STOP_ONCE pins final output SHA and predecessor build; neither grant embeds its own executable digest. The external build manifest binds accepted Source, toolchain/flags, exact grant bytes/digest and resulting executable SHA. Future operational review pins that output executable before use. A new STOP_ONCE executable cannot treat a caller's claimed review as accepted merely because its JSON is self-consistent.

16: ## Loading and immutable API
17: 
18: `internal/ownedcorestop/contract.go` declares package-private `var compiledOperationGrantBase64 string` with default empty. Root's reviewed build invocation sets it with Go `-ldflags -X researchos.local/research-os/internal/ownedcorestop.compiledOperationGrantBase64=<canonical-base64>`. This is a link-time payload in a dedicated binary; no CLI/env/config setter exists. Fixtures use the same real build option and production code. Do not mutate it from test Go code and call that a compiled-grant test.
19: 
20: `loadCompiledOperationGrant() (operationGrant, error)` is package-private, strict, bounded (at most64KiB decoded), and cached once. Empty/noncanonical base64, duplicate JSON keys, unknown fields, trailing data, invalid digest/path/identity/time fields or unsupported kind returns `STOP_GRANT_UNCONFIGURED`/`STOP_GRANT_INVALID` before DB, backup, process-handle or output-journal operations. The struct's fields are private. `newCompiledOperator()` (or the corresponding existing command constructor) takes no authority argument. Its preflight/commit/inspect methods always load that grant internally. There is no exported `SetGrant`, grant map, accepted bool, injected checker or callback. Internal pure validation tests may decode bytes, but production entrypoints obtain authority only from the compiled payload.
21: 
22: All caller arguments select files matching already pinned inputs; they supply no permission. `--expect-plan-sha256` remains an extra equality check and must equal the compiled expected SHA. It cannot be used with an unconfigured binary. A default/unconfigured CLI returning denial is safe-disabled behavior only; it is not complete usable Source acceptance. Non-Windows remains unavailable.

Each digest is a nonempty exact SHA256, not zero/placeholder/prefix. The compiled grant pins both final plan and its separate review/scope/evidence, and all subjects must agree across them. The final plan cannot add another native subject or another accepted proof class. The required class list initially remains the independently accepted strict classes; NEVER_JOB_AUTHORIZED cannot appear until separately accepted architecture/source and a later operation scope explicitly select it.

A matching hash is insufficient if document semantics conflict. Input indexes must resolve all member digests; missing required evidence is unavailable. Source/runtime validation still checks the real current SID, authority, native handles, schema/census and closure proofs; no grant can override a failed fact.

34: ## Lifetime and one-action rules
35: 
36: Each grant has an explicit validity interval of at most30minutes. Validate wall-clock interval at initialization, after long preflight/backup/lock waits, before BEGIN, and immediately before TERMINATE_INTENT. Within one invocation also use a monotonic deadline derived from the initially remaining interval, so a backward wall-clock change cannot lengthen that invocation. Expiration before termination means zero action and orderly reservation release. Expiration after a single action cannot authorize a retry: finish bounded native wait/postflight or record UNKNOWN. Expired inspect can read existing immutable journal receipts for this compiled operation only, with no new backup, DB connection, native probing, grant renewal or action.
37: 
38: Acquire an exclusive operation-directory lock before any journal creation/action; hold its non-reparse directory identities and private ACL checks until return. Plan, preflight manifest, BEGIN and TERMINATE_INTENT bind both grant digest and final plan SHA. Concurrent invocations with the same operation cannot both create an intent; a different compiled grant/plan pointing to that journal conflicts. Existence of TERMINATE_INTENT permanently consumes this operation's one action, even when the process died before calling TerminateProcess. There is no interpretation that missing NATIVE_EXIT permits another attempt.
39: 
40: The STOP_ONCE commit validates the grant and full immutable preflight chain, retains the exact target and parent handles, takes the reviewed SQLite barrier and checks current authority/census, then writes+flushes BEGIN and TERMINATE_INTENT with grant digest before the one TerminateProcess. Use the original retained handle for identity recheck, termination and wait; never reopen by PID after the barrier. Exact target already exited means zero termination and a separate observation. PID reuse/image/root/Owner/Host drift, unknown child/effect, stale backup or any evidence mismatch yields zero termination. Completed replay returns the same immutable outcome. `inspect` is observation-only and cannot call commit internally. A lost/torn journal or intent without reliable outcome stays UNKNOWN and cannot be repaired by deleting files or rebuilding the same grant.
