# CLI43 Root metadata preparation

PREPARATION ONLY. No script in this package was imported or executed. No registration, grant, compiler, native helper, database, HTTP or model call occurred. Root must obtain a separate nonauthor review and bind real public resources before use.

## Noncircular sequence

1. Root stages the six reviewed wrappers, byte-for-byte, in a new explicit `integration_codex` registration namespace. The pinned common module stays at its immutable receipt path. Root freezes these actual code paths together with Python `__file__`, `__cached__`, executable and actual OS resources. No guessed DLL or compiler catalogue is supplied here.
2. Root supplies every required `build_binding.proposed.py` CLI parameter. `--controller-review-ref null` is valid only for this pre-review scope stage. `scope_builder.py` then writes a fresh scope from `scope.v3.proposed.json` and this pre-review binding. A scope is still insufficient for any case execution.
3. The independent controller reviewer reads that completed scope and signs its complete SHA plus runner, launcher and v3 gate SHAs. The scope contains only the predetermined `controller_review_path`; it does not contain this future review's SHA.
4. Root creates a separate final `binding.json` with the actual review ref and otherwise identical supplied values. `prepare.py` saves all four originals and desired bytes, with changes confined to checkpoint/ownership; step_state and commands remain byte-identical. Root reviews the exact resulting metadata scripts, prepared refs and audit using a separate nonauthor registration review.
5. `run.py` starts `register.py` once inside the pinned owned Windows Job. Register emits an immutable two-file intent before temporary files, compares all four current byte strings plus Git HEAD/status/index before each replace, records each completed own write, and verifies the final four bytes. Any failure stops without automatic retry, reset or rollback. Recovery is a separate Root forward-only decision using original/desired/current hashes.
6. `seal.py` accepts only the actual child invocation, raw output hashes, done records, verified intent, exact desired current bytes, preserved failure prefix and Git guards. It creates the actual registration audit and manifest. A metadata script's report alone cannot substitute for the invocation.
7. `grant_preflight.py` verifies that sealed registration using the v3 gate, copies the four actual canonical bytes to a fresh authorization directory, performs only owned read-only Git preflight and Python/OS point observations, writes the bound grant, and calls the pure gate verifier. It never invokes the launcher. Root separately invokes the original pinned launcher once after a completed grant.

The dependency order is **code + actual resources + source authority + planned review path → scope SHA → independent controller review → actual checkpoint reference + independent registration review → CAS and seal → copied canonical/grant → launcher**. No future review hash is embedded in the scope it reviews.

## Required CLI inputs

All refs are exact JSON objects `{ "path": ..., "sha256": ..., "bytes": ... }`, not guessed filenames. All scripts require pinned Python `-I -S -X utf8`.

`build_binding.proposed.py` requires:

- `--scope-template-ref`, `--runtime-resources-ref`, `--compiler-resources-ref`, `--source-inputs-ref`, `--current43-authority-ref`, `--origin-cut-ref`, `--canonical-before-ref`, `--failure-prefix430-ref`, `--metadata-code-refs-ref`.
- `--before` and `--after` as explicit three-integer JSON arrays; no future tuple is inferred from live state. The first registered 430 origins are compared to the explicit immutable 430-origin checkpoint ref. All later original entries are also preserved, and only the explicit origin cut is appended.
- `--main-git` as exact current HEAD/status SHA/status bytes/13 rows/11 deletions/empty-index object; `--public-environment` limited to SystemRoot/WINDIR/ComSpec/PATH/PATHEXT.
- `--run-uuid`, `--registration-namespace`, `--controller-review-path`, four disjoint new roots (`--new-output-root`, `--new-wrapper-root`, `--new-export-root`, `--new-authorization-root`), and `--output` for the immutable binding JSON.
- `--controller-review-ref`: literal `null` before scope review; actual exact ref for final binding. There is no inferred review or automatic review delivery claim.

Six wrappers require `--binding-ref` and `--output` (the already-created exact Root registration directory). Scope builder additionally takes `--scope-template-ref`; prepare and grant take `--scope-ref`; register and run take `--review-ref` (independent metadata review). Seal uses the recorded actual invocation's review ref. No supplied binding has authority to bypass those checks.

## Supplied JSON shapes

- Resource/source inventories: `{files:[exact refs]}` or `{entries:[exact refs]}`; caller must normalize existing richer source catalogues explicitly without altering their original evidence. Raw Git-mode/catalogue rows are not silently treated as exact refs. Actual file inventories must include all metadata module/wrapper paths used at runtime. Runtime observation through the unchanged controller is a before/after point observation, not continuous Python lifecycle proof.
- Canonical-before bundle: `{entries:[{canonical_path,ref}, ...]}` in checkpoint, path_ownership, step_state, commands order. Each ref points to immutable actual original bytes, and live bytes must equal them when preparing.
- Origin cut: `{before,after,counter_reset:false,origins:[...]}`; each original row carries `evidence_ref`, exact `original_payload` and `counter_reset:false`. Native and outer values remain the original nullable values. No assumption is made about current pending count.
- Metadata code refs: `{entries:[exact refs]}` includes the six staged wrappers and common module/builder inputs. Catalogue inputs themselves must be independently frozen by Root.
- Current43 authority is the gate's existing `researchos.cli43.current-source-validation-authority.v1`, including actual sealed Main38, CLI8 and head-forward evidence. This package cannot manufacture that authority from a commit name.
- The actual registration manifest uses `entries/count`, includes scripts, binding, originals, desired, audit, invocation, raw stdout/stderr, intent, done and verified files. Its only exclusion is itself. Grant's immutable input closure also includes actual independent reviews and all referenced manifest members.

## Boundaries and limitations

Only checkpoint revision/history/WIP's three exact CLI43 keys and ownership revision/timestamp fields are prepared to change. No product path, index, HEAD, state, commands, existing owner/subtask, formal verdict or old failure is changed by this design. The Root ownership revision records the metadata transaction; this template creates no new product source lease.

Future grant Git calls have the exact gate-compatible argv, fixed no-optional-lock/no-fsmonitor/no-untracked-cache environment, and dedicated owned Jobs. No bare-PID termination or taskkill exists here. Registration's child limit is 600 seconds; each read-only Git child is 30 seconds, cleanup remains the pinned helper's behavior. Product runtime limits remain the original two cases, 32 upstream dispatch + 32 proxy admission per case, observed qualification bound 128, unknown unobserved client outbound bound, and zero SDK/model/Node/external/paid/private calls.

Pre-owned-output failures are emitted to raw stderr for Root's caller to preserve. Once a safe leaf exists, first-cause receipts are immutable; secondary save errors do not replace the first cause. Stage-native values remain NULL unless an actual owned child result was collected. Partial grants, partial canonical transactions or missing final manifests never authorize launcher execution. Future actual resource shapes, tuple, source authority, independent full-scope review and metadata review remain mandatory and unbound.
