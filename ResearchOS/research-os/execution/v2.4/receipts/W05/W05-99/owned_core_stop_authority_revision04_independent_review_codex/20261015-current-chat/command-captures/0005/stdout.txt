# r4 selected image path boundary (author analysis)

The selected Core and parent image are actual copied task-owned processes. The native open walks from the volume root through every selected component, rejects reparse points and final-image hardlinks, checks owner and DACL at each handle, hashes the final image through its retained handle, and keeps those handles until after the native action. Its grant and plan bind each process/image identity separately. The path policy allows the current operator SID and the named OS/install owners (SYSTEM, Administrators, TrustedInstaller). An otherwise valid foreign owner or an effective untrusted allow ACE for write, delete, or security control is rejected. Unsupported ACE types and malformed ACEs fail closed. `INHERIT_ONLY` is skipped only on the component on which it does not grant access; a grant inherited onto a selected descendant is checked on that descendant.

Relevant mutations are edits to the selected final image, unlink/rename/replacement of a selected file or directory component, or changing its owner/DACL. The final image handle is retained with `FILE_SHARE_READ` and therefore an incompatible writer/delete opener fails. Every selected ancestor is also retained without delete sharing; swapping an existing selected component requires delete access to that component. The policy rejects untrusted `FILE_DELETE_CHILD` on directories and rejects untrusted write/control ACEs. It permits the isolated `FILE_ADD_SUBDIRECTORY` bit on an ancestor because it can add a sibling but cannot remove the existing selected child. A directory `GENERIC_WRITE` open **did succeed** in the task-owned fixture after retention; the test does not treat that fact alone as a replacement. With that writer open, selected ancestor rename still failed. Final-image write, removal, rename, same-name replacement, and selected ancestor rename failed while retained. A later DACL change on the held image made `verifyRetained` fail on the same handle before action. The final boundary re-observes handle ID and owner/DACL and verifies Core/parent process identity and liveness.
