## Broker completion fence

Current runCommandBridge increments inflight and starts broker goroutines but returns directly on a non-cancel-fenced error. Waiting for Bridge.Done() therefore does not prove host broker completion. B adds a per-dispatch private broker admission registry: ordinal, frame digest, launched/completed state and completion digest. The registry is owned by the runCommandBridge invocation, uses one mutex for admission/closure, and is not persisted as authority or exposed to renderer JSON.

On the first typed rejection, stop admitting new broker work, retain the original cause, cancel the dedicated broker context, cancel the bridge, and continue draining already submitted result completions and captured frames. Every launched goroutine must finish and join; all completion deliveries are consumed exactly once. No new frame is ACKed after the typed denial. Record any extra suffix/frame/stream activity as a disqualifier. Enforce bounded wait: timeout produces UNKNOWN and cannot yield a success/closed ticket; worker shutdown alone cannot replace this wait. No late goroutine may use a context that survives the fence. Generic error paths keep UNKNOWN but also cancel/join before leaving the scope where possible; if an external call cannot be proven ended, remain UNKNOWN. A private `qualificationBrokerDrain` ticket has no exported constructor and records accepted=completed, pending=0, admission closed and exact frame digests. The closure constructor requires this ticket, not a caller boolean.

Cancel heartbeat and await heartbeatDone before taking the terminal transaction and final Run CAS, to avoid a late heartbeat changing the baseline. Preserve the first cancellation reason in bridge_windows.go; subsequent timeout/context/cancel causes may be recorded as secondary facts without changing the first cause. This is not permission to hide a later native failure.
