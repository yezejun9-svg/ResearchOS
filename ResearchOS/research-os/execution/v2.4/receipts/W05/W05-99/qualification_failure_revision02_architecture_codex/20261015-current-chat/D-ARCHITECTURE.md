## Decision: existing schema24, no DDL

Use immutable `idempotency` rows as exact indexes and Owner-authored sealed Artifact content as append-only lineage. The existing primary key `(principal,project,operation,key)` and immutable update trigger are sufficient when all index validation, Task/context/Plan creation and new confirmation insertion occur in one serialized transaction. No mutable latest-attempt column/table, rowid ordering or new migration is permitted. New runtime_bindings rows are forbidden for this follow-up: reuse the existing exact row.

An attempt is identified by `{lineage_key, attempt_id, attempt_sequence, task_id, plan_hash, profile_ref, profile_hash}`. `lineage_key=Hash({project_id,runtime_id,owner_id,owner_root,profile_ref})`. The actual next attempt preserves the same Goal, active budget ancestry, immutable profile and model configuration; creating a new Goal/policy is OUTSIDE D v1. Only explicit new Owner intent creates a next attempt. An old confirmation always addresses its own old immutable request and consumed Run.

## Exact immutable records

Operations are fixed private namespaces:

1. `host:qualification-fresh-intent`, principal=current Owner, project=exact project, key=intent_id, request_hash=Hash(canonical FreshIntent), status=200, body=canonical PreparedAttemptResult, headers='{}'. This is request-idempotency, not an execution queue. Same intent id plus different hash rejects; identical id/hash returns the same frozen result without mutations. Expiry does not silently create another attempt or confirmation.
2. `host:qualification-attempt-index`, same principal/project, key=`<lineage_key>/<20-digit sequence>`, request_hash=Hash(canonical AttemptIndex), status=200, body=AttemptIndex, headers='{}'. AttemptIndex includes schema, lineage_key, sequence, attempt_id, task_id, plan_hash, profile_ref/hash, lineage_artifact_ref/content_hash, predecessor_index_hash, intent_id and original confirmation_request_id/hash. Unique sequence is a consequence of the existing PK plus serialization; no INSERT OR IGNORE.
3. Existing `host:qualification-confirmation` row remains the actual one-call intent. New request struct fields are optional `attempt_id`, `attempt_sequence`, `lineage_key`, `lineage_artifact_ref` with omitempty; legacy request canonical bytes/hash MUST remain identical. `host:managed-runtime-qualification` remains the once-only consumed record at execution, and is NOT created by preparation.

FreshIntent schema is `researchos.qualification-fresh-intent.v1`, strict known fields: intent_id; Owner/Host/root; project/session/model configuration identity and current session hash; prior_request_id/hash; prior_task_id; prior_run_id/epoch; prior closure kind/Artifact ref/content hash; prior_attempt_id/sequence (legacy root has derived sequence1); immutable runtime/profile binding; expected lineage head hash; explicit action `PREPARE_NEXT_ONE_CALL`; max_model_calls1/max_tool_calls0. Desktop main derives all authority-bearing fields from selected context and a fresh Host STATUS; renderer supplies no IDs, token, paths or SQL. The user action is separately labeled as preparing another attempt. The intent hash is bound to that user action and retained for status/retry of preparation only.

Lineage Artifact content schema `researchos.qualification-attempt-lineage.v1` carries author Owner/root/Host, observed_at, intent/hash, immutable binding, sequence, predecessor Artifact/index hash, prior Task/Run/request/closure hashes, new Task/context/Plan hashes, current ancestor policy refs, prior NoProgressRecord id/key/hash/counters and declaration `model_calls_during_prepare=0`. It is a new current maintenance/preparation document, never attributed to the old executor. Seal with `produced_by=currentOwner`, `run_id=null`, kind MANIFEST, evidence_kind GENERATED, mode LIVE (FIXTURE in tests), access PROJECT. Its content, not the original Run input vector, carries lineage.

Outer Artifact input_refs are immutable profile ref plus prior closure Artifact and prior lineage Artifact when present; all must be validated exact versions. Old Run/Task/NoProgressRecord revisions are historical subject hashes inside the envelope, not new Task inputs. No `runtime_uploads`, `artifact_uses` or `artifact_use_proofs` row is created for this non-Run Artifact. Existing seal with run_id=null records only the upload, Artifact/ref/version and DERIVED_FROM ImpactLinks for its outer refs. Do not use recoverArtifact, which assigns the old executor and original Run.

For an existing lineage, enumerate fixed-namespace rows for the exact binding; verify every canonical body/hash, contiguous sequences from1, immutable Artifact, predecessor hash, Task/Plan/profile and original confirmation. No automatic attempt is created from startup, Scan, configuration setup, STATUS or receipt recovery.
