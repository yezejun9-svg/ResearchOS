# Chooser diagnosis controller revision01

This revision supersedes only the prepared controller and Native3 client in the parent `preparation/` directory. Both parent files remain byte unchanged. Product commit `5c4c94022bd92da68ef544f2779527bfe065c428` remains frozen; no native product run was made.

The controller requires a fresh Root scope whose `bound_files` pins this controller, this PowerShell client, the existing `driver-v2` owned-folder confirmation and owned-window close scripts, and `installed-product.json`. Its fresh state root must be beneath the worktree `.local`; its fresh receipt root must be beneath `native-init-diagnosis-02` and outside `preparation/`. It starts one Electron/Core pair and sends at most one workspace-choice Native3 frame. The PowerShell client checks the pipe server PID and Core PID, creation time, image and hash against the READY witness before and after the reply; it preserves the full raw response, including the existing `NATIVE_ERROR.error.message`.

Each successful `Popen` is appended to `OWNED_HANDLES` before receipt writes or stream closes. A failed receipt, console print, helper, timeout, or close check leaves the controller in a Root-release wait loop. A release must be a new `ROOT-RELEASE.json` created after `WAITING_FOR_ROOT.json`, with exact schema `researchos.native-chooser-root-release.v1` and fields `actor=codex:/root`, `scope_sha256`, `controller_pid`, `release_nonce`, `known_identities`, `root_confirmed_identity_absence=true`, and a timestamp after wait entry. The controller then runs two consecutive read-only process scans at different times. Each scan selects every process whose name matches an EXE in the exact installed bundle **or** whose PID is known from an owned handle or witnessed Core. It refuses release for an exact bundle image, a still-live or reused known PID, an unknown candidate identity, or any scan/logging failure. No automatic retry, force kill, state deletion, or witness deletion is provided.

After normal owned-window close, `RESULT.json` claims `OWNED_PAIR_CLEAN_CLOSE_CONFIRMED` only if the exact Electron and Core PIDs are absent, Electron exited 0, and the witness retired. If the pair is absent but exit or witness retirement is unproven, it writes `PAIR_ABSENT_CLOSE_UNPROVEN.json` and enters Root-release wait. The success/error Native3 reply is never equated with product acceptance.
