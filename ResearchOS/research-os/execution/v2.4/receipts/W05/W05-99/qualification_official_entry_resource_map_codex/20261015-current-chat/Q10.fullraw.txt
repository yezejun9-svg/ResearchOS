1:# Windows x64 R1 fixture bundle
2:
3:This ZIP is a reproducible **development fixture**. It does not install an SCM service, enable normal LIVE runtime execution, qualify a provider, activate a populated database, or satisfy clean Windows A15.
4:
5:The [Chinese workbench guide](user-guide.md) explains all eleven implemented screens, permissions, result states, and the existing screenshot index. Those screenshots are external historical evidence in the source checkout; they are not bundled. Using the UI requires an already authorized service and credentials; the fixture launcher does not issue login credentials or remove activation restrictions.
6:
7:Build from a frozen source commit on a Windows x64 build host with the exact locally provisioned Go 1.27.1, Node 24.9.0, npm 11.6.0, and Python 3.14.3 recorded in `execution/toolchains/locked.json`. The builder rejects dirty, missing, and untracked files across the package and Go/web build input trees, checks the source against HEAD before and after building, verifies tool hashes, uses `GOTOOLCHAIN=local`, runs `npm ci --offline`, and never invokes the repository's full-test CI script. Unrelated execution evidence can remain untracked. Its external JSON output records the archive SHA-256. Use two separate invocations and compare both archive hashes and every manifest file hash before distributing a candidate.
8:
9:```powershell
10:$py = '<verified Python 3.14.3 path>'
11:& $py ops/release/build.py --output 'C:\release-output\researchos-r1-a.zip'
12:& $py ops/release/build.py --output 'C:\release-output\researchos-r1-b.zip'
13:Get-FileHash -Algorithm SHA256 'C:\release-output\researchos-r1-*.zip'
14:```
15:
16:Extract one ZIP into a new directory. Keep that directory read-only during operation. The manifest lists every packaged file except itself; verify it and compare the archive hash with a separately approved distribution receipt. The manifest and hashes establish integrity, not independent source trust or a signature. The package contains no development tool paths. Its `licenses/` entries contain locally present license texts; `sbom.license_gaps` remains an explicit release gap where a text was unavailable. The bundled `execution/commands.json` is the real construction registry; `release.reproduce` and other `UNBOUND` entries remain nonzero. Construction checks require an exact source checkout, pinned tools, and their own evidence roots. The bundled scripts do not turn those checks into installed-product acceptance.
17:
18:Use a new **absolute** data path outside the extracted package and a free loopback port other than 32736 or 79136. The example runs without credentials and creates only a fresh fixture database. `-Fresh` rejects existing data. It never points at the protected broker, an existing ResearchOS product database, or a production provider.
19:
20:```powershell
21:$release = 'C:\release-output\researchos-r1-extracted'
22:$data = 'C:\release-output\researchos-r1-fixture-data'
23:& "$release\scripts\verify.ps1" -ReleaseRoot $release
24:& "$release\scripts\start.ps1" -DataDir $data -Listen '127.0.0.1:19878' -Fresh
25:Invoke-WebRequest 'http://127.0.0.1:19878/healthz' -UseBasicParsing
26:& "$release\scripts\stop.ps1" -DataDir $data
27:```
28:
29:The fixture stop script validates the recorded PID, process creation time, executable, and OS command-line instance/data/release binding before stopping the owned process. A missing or mismatched process leaves the identity file and data untouched. It preserves that directory, logs, and database. It is not the production drain/checkpoint/SCM protocol. To disable this fixture, stop it and leave data in place. To remove the package, delete only the extracted release directory after stopping it; retain data and receipts separately.
30:
31:The existing exact `schema13-to14-remote-access-v1` upgrade remains unchanged. The separate `schema13-to20-research-runtime-v1` plan pins all twenty frozen migrations and has bounded fixture evidence for preservation and recovery. Actual populated-database activation remains blocked; the fresh fixture launcher does not perform either upgrade.
32:
33:The package also includes `bin/release_host.exe`, the existing same-user fixture supervisor. Its persistent actual-control host, private READY checks, exclusive data-root lease and encrypted cutover snapshot mechanisms have bounded evidence. Restricted offline replay of the real control executable has bounded no-gain evidence and retains the stable slot. The scripts above still use the direct fixture start/stop path. Current-authority release proof and complete different-build cutover/rollback remain closed; the supervisor binary does not grant that qualification.
34:
35:Clean Windows installation, independent service identities and ACLs, actual update/rollback, W19 overnight evidence, and the full 42-case acceptance index remain incomplete. A successful current-user fixture run is evidence only for the packaged fixture start/stop path.

52:## 2. 研究工作台
53:
54:先看“持续目标”“业务已验收”“待评审”，再查看意图规划、当前推进、来源覆盖、最近成果和下一步。业务统计排除意图规划及运行器资格任务；规划提案检查通过只说明规划可追溯、可检验，业务成果另行验收。
55:
56:提出工作时点击“提出新想法”，填写原话，再点击“确认原话并开始规划”。页面先保存原始 Requirement，再由同一用户确认原话，授权生成可审查规划。未完成提交的原话及提交身份保存在当前浏览器的项目草稿中；刷新后“继续提交”延续同一份提交，已开始的原话会锁定。若出现版本变化，核对原话后使用“核对后重试”，不要反复另建相同想法。
57:
58:提交成功后从“意图规划”打开对应任务，查看规划、资源缺口及独立检查。点击“当前推进”中的任务可查看执行细节。此页面没有一键宣布业务成功或绕过验收的功能。
59:
60:阶段侧栏显示各阶段“已验收 / 计划”及进行中、待评审、受阻数量，同时显示计划修订与事件水位。新计划增加任务时分母可能变大；这不表示已验收结果被撤回。未取得投影时显示尚不可用，不推算完成百分比。

63:

70:## 4. 任务详情
71:
72:页面上方显示任务状态、修订、冻结输入数量和当前 Run 状态。通过“摘要 / 过程 / 产物 / 检查”切换：摘要看执行报告和输入；过程看运行器、执行者、时间与最近关联事件；产物查看封存内容；检查查看独立验收结论及实际检查命令。标签支持方向键、Home 和 End。

104:“评测资格”列出服务返回的资格记录，不能将任意一条列表记录当成当前实验的资格证明；开发夹具也不替代正式资格。费用与完整性以关联报告为准，没有报告时保持未知。对于可访问的聚合评测 JSON，受控预览可展示预期、观测、通过、失败、错误、弃权、缺失、重复计数，以及费用、完整性和固定哈希。正式留出逐题内容不在工作台展示。

120:## 10. 费用与资源
121:
122:先看当前金额策略和待处理资源，再读逐笔账目。“未知或待结算”对应缺少金额的记录，底层 `money=null` 不是金额 0；`UNKNOWN` 也不应计为已结算。页面按运行与供应商请求的最新记录区分已结算、在途预留和未知，同时保留逐笔金额、币种及费用依据，不提供跨币种合并总额。
123:
124:获授权 Owner 可在“修改项目上限”选择“不设金额上限”或“设定上限”。设定上限时填写金额、币种，并选择严格上限或按估算执行，点击“保存上限”。严格上限在费用未知时阻止新执行；估算方式允许记录未知费用，不能保证最终账单不超额。不设上限也不代表无限余额、供应商可用或没有并发限制。
125:
126:每条资源请求列明原因、受阻任务、可继续任务、保留产物、预计费用与恢复检查点。处理完实际缺口后，点击“登记解决”，填写解决依据，选择封存产物或来源证据，输入已有 ID，再点击“提交服务核查”。页面先读取并固定依据的修订，服务检查请求状态与引用有效性后登记解决；这不证明外部资源已恢复可用，也不直接恢复任务。输入错误、权限不足或版本变化时根据提示修正后再试，仍需核对后续执行状态。
