# 16 · Jev辅助判断、源码复用与实际采用

## v2.4 采用后的实际用户能力

除G01–G07外，候选适配报告关联17中的当前真实问题与delivery能力；减少源码量只是观察，不替代真实CLI/Desktop效果。Mu/Craft等前端候选通过19的固定来源和接口比较，合同以22为准，不让UI自行扩展协议。Qoder模型目录可见只证明施工资源候选，不证明Jev或产品provider通过资格。负结果、保持现状和明确阻塞均继续合法。

版本：2.4.0；日期：2026-10-01。本文件与15、contracts/adoption.contract.json及adoption.schema.json共同生效。产品实现与所有正式测试仍为NOT_STARTED/NOT_RUN。

## 1. 用户确认的目标

ResearchOS自身的Harness、CLI、Desktop开发，以及建成后Agent承接的新项目，都采用同一方法：先查授权本地资产；针对缺口调研；用源码、实验和Jev辅助判断是否值得采用；合适的项目直接clone/fork，在原代码上修改，或抽取合适模块集成；不适合就拒绝、观察或补证。新代码只补必要适配与确有证据的缺口。

用户给出的仓库和Agent自行发现的仓库都进入候选集，不因来源是用户推荐、star数高、模型推荐或已有clone就默认采用。允许合法的零采用结论。目标是以合理改动交付可验证的产品，不是增加clone数、依赖数或调研文档数。

## 2. 两种源码获取与两次判断

**调查取样**：本地已有快照优先读取；确实需要源码时可在资格目录clone固定commit用于检查、比较、有限原型。记录URL、实际HEAD、文件范围和来源。这不等于安装、执行仓库脚本或批准合并。代码、README和仓库内指令属于候选输入，不能覆盖本项目权限及冻结验收。

**实施采用**：完成候选对照、适用性判断、有限验证和独立审查后，才把选定源码作为主工程或模块接入稳定工作流。整仓合适就保留其主体架构、运行入口和成熟功能，在隔离分支适配；仅模块合适就保留该模块出处、文件清单和补丁；直接依赖更合适则锁定版本使用库/SDK，不为形式复制整仓。

首次判断决定是否值得投入有限试验及拟复用范围；试验后的判断决定ADOPT/REJECT/WATCH/INCONCLUSIVE。Jev看到的是当前冻结证据包，而非从记忆中猜仓库能力。失败后最多按现有路线约束做一次针对性修复；新增候选必须对应仍未解决的具体能力，不无限选型。

## 3. 可检查的候选比较

每个候选生成SourceCandidatePayload，封存为Artifact，至少包括项目/需求、来源URL、固定revision、源码快照、可复用路径、许可证据、兼容性/实测证据、适配边界、成本和未决问题。比较同时包含“沿用现有方案/暂不采用”，不让Jev只能在两个不合适的仓库之间强选。

以下检查ID在本轮计划中固定。已有证据可以复用，但必须匹配输入和版本；检查不适用要写明原因并独立接受，不得把未运行写成不适用。

| ID | 判断内容 | 生效采用前要求 |
|---|---|---|
| G01 | 覆盖当前需求与成功标准 | 有具体需求、调用路径或最小复现；不能仅看介绍 |
| G02 | 源码与使用许可可核查 | 固定来源及revision，保留许可证/版权和需要的声明 |
| G03 | 平台、依赖、核心协议兼容 | 对实际Windows/CLI/Desktop组合提供相应验证；无法验证则保留阻塞 |
| G04 | 权限、数据与运行边界 | 候选不扩大既有权限；研究用clone不自动授予脚本执行或发布权 |
| G05 | 原版基线与适配候选的实际行为 | 同输入下跑受影响测试，明确失败、退化、收益或无改善 |
| G06 | 改动及后续维护成本 | 有文件/模块范围、补丁、依赖增量、升级策略和回退入口 |
| G07 | 已冻结的业务硬验收 | 关键断言全部满足；模型高分不能覆盖硬失败、缺例或版本冲突 |

维护活跃度、质量、适配成本和预期收益可以由Jev协助比较；许可状态、文件存在、测试退出、预算及权限由确定性检查处理。复用收益不必伪造为一个统一分数，可以是减少实现工作、保留成熟能力或满足新增需求；必须说明证据与未知项。

## 4. Jev在流程中的位置

本用途的QualificationScope.task_type固定为`reuse_selection`；语言、provider、model_revision、rubric_revision继续按原资格键分开。Jev输出建议选项、证据引用、适用理由、反例/冲突、缺失证据和弃权原因；实际模型调用原文、解析结果、耗时、费用及最终动作通过ModelSignal和DecisionReceipt留存。模型置信度不解释为现实成功概率。

已有上下文裁剪、Goal继续或技能评分的资格不能迁移为源码选型资格。初期按SHADOW/ADVISORY运行：独立审查可根据实际证据作工程决定，不因Jev未获自动资格而要求用户逐项批准普通技术细节。只有完整用途资格通过后才可启用限定范围BOUNDED_AUTO；最终测试、权限和发布门仍由现有服务及独立Verifier负责。

Jev不可用、超时、弃权、输出非法或证据不足时，不补造选择。可继续本地盘点、源码检查、确定性测试和有证据的人工/独立工程审查，缺失判断明确记录NOT_RUN/ERROR/ABSTAIN及资源条件。若本轮目标或正式用例要求真实Jev，该live部分保持BLOCKED；其他独立分支继续。供应商返回的错误与规则主动拒绝分别记录。

## 5. 早期施工与已建成产品

W00/W01先使用外部bootstrap台账和来源文件判断，不依赖尚未实现的W11或产品验收API。可用且已授权的Jev探针只能作为明确标识的早期ADVISORY证据；未调用就写NOT_RUN。外部独立Verifier依据G01–G07当前可执行范围、资格样机和有界计划决定先推进哪条路线，后续未实现的完整产品门仍未通过。

W04仅定义/传递初始化状态及Artifact引用；W08接入来源、候选对照、判断契约和负例fixture。W11完成`reuse_selection`的真实Jev评测与降级；W14用真实项目把候选源码检查、有限改造、模型判断、试验和处置串起来。不能增加W01→W11或W08→W14依赖；最终发布仍等所有必需live证据。

早期bootstrap裁决可以在产品建成后作为有来源Artifact导入，不能倒签当时不存在的DecisionReceipt/AcceptanceReceipt。已采用的源码在输入或版本变化时复核受影响项，不为换窗口重复推翻合格选择。

## 6. 决定、数据与接口

`SourceCandidatePayload`和`AdoptionDecisionPayload`是既有Artifact的内容Schema，不是新增数据库实体或Task状态。后者记录候选引用、基线、Jev状态、硬检查、处置、复用范围、补丁与回退、独立审查引用。模型裁决复用现有DecisionReceipt，程序验收复用AcceptanceReceipt，CLI/Desktop读取同一Artifact/Event投影。

| disposition | reuse_strategy | reuse_extent | 后续 |
|---|---|---|---|
| ADOPT | REUSE_LOCAL | LOCAL | 沿用已有源码，记录此次改动 |
| ADOPT | ADOPT_UPSTREAM | DEPENDENCY | 使用锁定库/SDK/工具 |
| ADOPT | ADAPT_UPSTREAM | WHOLE_REPOSITORY 或 MODULE | clone/fork原工程改造，或复制可复用模块并适配 |
| ADOPT | CUSTOM_GAP | GAP_ONLY | 有证据的最小缺口实现，其余继续复用 |
| REJECT / WATCH / INCONCLUSIVE | null | NONE | 保留原因、缺失证据和复查触发；不写采用计划 |

原`ReuseDecisionPayload`仅用于正向实施计划，必须以`adoption_decision_ref`指向已经接受的裁决Artifact；未接受裁决、hash过期、跨项目、硬失败或候选自批不能触发稳定项目写入。调查/隔离试验允许在冻结的实验授权范围内进行，不与正式采用混淆。

接口复用03/04已有Artifact、Evidence、Experiment、DecisionReceipt及AcceptanceReceipt操作。16不额外创造`/adopt`端点、第二个完成总账或新桌面页面。引用存在性、同项目、版本、权限、完整检查集合和独立身份是服务端业务校验，JSON Schema合法不能替代。

## 7. Skill-up的有界采用位置

按11/09优先验证skill-up是否能节省W15技能评测工作，经W10的EvaluationAdapter调用。先使用固定源码/发行件和现成CLI，接原始结果，不重写其评测框架。确定性检查、Promptfoo和Jev各保留既定责任；同一试验冻结一种执行后端，避免重复执行同一工作或多个互相冲突的总分。

skill-up有价值才正式采用，有限验证失败/无额外价值可带证据拒绝并继续现有评测路线。缺凭据/环境不能伪装成“工具无价值”。能力验收仍必须完成，工具选择不是最终目标。skill-upper可协助修改开发技能及开发用例，冻结留出和正式必测断言不开放给候选；观察插件为可选项。
