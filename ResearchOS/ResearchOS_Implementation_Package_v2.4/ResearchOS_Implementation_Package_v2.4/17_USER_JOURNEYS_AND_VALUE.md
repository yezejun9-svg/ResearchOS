# 17 · 真实工作、首日使用与价值验收

版本：2.4.0；日期：2026-10-01。本文把使用目标落实到现有 R01–R20 / W00–W21 / 42 例，不删减完整首版。机器定义见 contracts/delivery.contract.json；执行顺序见 contracts/execution.plan.json。所有产品结果仍为 NOT_RUN。

## 1. 已确认目标与可执行默认

USER_STATED：交付自己的完整 CLI Agent 与 Windows Desktop；桌面具备 Claude/Qoder 一类产品的直观会话和编码工作区；允许复用合适开源前端；由 Qoder 使用 Qwen3.8-Flash 经 /goal 实施。原有研究、Jev、连续目标、协作、隔夜、手机监督和恢复要求继续有效。

ENGINEERING_DEFAULT：先交付一次可亲自使用的编码任务，再闭合研究到采用，最后验证自我改进与全量发行。完整范围不缩减，早期可用不能标成完整产品 DONE。每个研究主题必须关联当前项目中的问题或用户明确的监控意图；不因新框架出现而扩大项目目标。

首个项目继续是 ResearchOS。复用旧仓库中的实际问题、文件与测试，禁止扫描其他私有项目。首次可用门固定为 ISSUE-FIRST-USE-001：消除手工管理命令和复制短期 Owner token，让 Desktop/CLI 经本机身份鉴别后接入同一受保护宿主。首次可用门可能在构建期间已完成；产品Agent的第一件编码任务须在演示前从当前未解决问题中另行冻结：先复现尚存在的缺陷，已完成则选下一项已要求但缺失的能力，例如 researchos doctor --json 的真实环境诊断。记录 issue_ref、当前失败复现、允许文件、用户可见预期、冻结测试和独立接受者。不得回退已有修复、人为植入缺陷、以无改动或重复重写冒充真实编码成果。只在候选代码及新测试数据根中实施和演示，不改正在运行的旧数据库、已有受保护服务或已被规则拒绝的启用动作。

第二件真实工作固定为 ISSUE-CONTINUITY-001：同一任务从 CLI 交给 Desktop 查看 diff/工具结果，再回 CLI 继续；旧客户端不能同时写，重开无需重贴目标。第三件真实工作固定为 ISSUE-REUSE-001：针对一个已登记缺口，实际核查 GitHub、X、论文，做有界实验，保留采用或拒绝证据；有价值才引入代码。三项可拆步实现，但最终必须用产品入口完成。

## 2. 首日使用流程 JRN-01

前置：干净 Windows 用户环境、已授权模型资源、已固定版本的候选发行件；模型凭据由测试者经遮罩界面输入，或经已授权凭据后端引用。不得让测试者安装 Node、启动数据库、生成 JSON、查日志找 token 或手工启动后台网页。

1. 安装并打开 ResearchOS Desktop。首次引导说明本地工作区、当前模型连接及是否支持后台运行；不展示伪造会话或已完成进度。
2. 使用系统目录选择器选择当前 ResearchOS 的隔离候选工作区。注册规范化路径；取消选择无副作用；同名目录按永久身份区分。
3. 选择模型，使用受保护输入配置已有资源，点击检查连接。分别显示目录可选、认证可用、真实推理、工具执行的已验证层级；一次模型回复不能冒充工具可用。
4. 进入真实会话，输入按第1节冻结的未完成 issue_ref 及任务描述。显示它读取了哪些文件、准备修改什么、运行了哪些命令；常规已授权操作直接继续。
5. 查看实际 diff 和测试输出。文件打开、搜索、复制、长输出展开、错误重试均可用；不能只展示报告卡片。
6. 关闭并重开窗口。按设置恢复相同项目、会话、未完成下一步；本地身份续接在宿主处理，用户不复制新的 15 分钟 token。

验收：用户为弥补产品缺陷而运行的内部管理命令数为 0；重复粘贴已经保存的背景次数为 0；示例任务的读、改、测试均有真实回执；界面与实际文件一致。首次配置已有账户本身不是产品缺陷。首次就绪用时、点击数和人为等待分别记录，初始体验目标为排除模型外部等待后 15 分钟内完成安装配置并进入任务；超过目标须记录原因并改进，不能删去必需步骤。功能硬门和体验观察分别记录。

## 3. CLI 完整流程 JRN-02

安装后从任意授权项目目录直接运行 researchos。默认进入交互模式；支持多行中文、粘贴、流式响应、工具折叠/展开、模型选择、会话恢复、错误定位、Ctrl+C。init、run --output jsonl、goal、resume、status、cancel、doctor、config 和 /help、/model、/goal、/status、/resume、/cancel 都有真实处理器。

输入“按已冻结的真实问题 <issue_ref> 读取相关实现，完成所要求的修复或功能增量，运行冻结的相关检查并展示 diff”。先读实际代码；已有实现可用则直接调用和适配，不重新全网选型。模型固定时不得静默切换。用户中途追加信息为 STEER/FOLLOW_UP，不能丢失或开启第二个写入进程。JSONL stdout 每行都能解析，诊断走 stderr；0 只表示执行结果完整报告，最终验收另读回执。

验收包含：中文及空格路径、长输出、命令失败后有限修复、模型资源缺失、拒绝越界路径、取消一个有子进程的工具、取消后不被 /goal 自动重启，以及从已有 session-id 继续。不能用外部 CLI 探针替代自己的 researchos 可安装入口。

## 4. 双端接续 JRN-03

CLI 发起并完成一次文件修改后停在可中断点；Desktop 打开同一 session，显示同一输入、工具事件、文件 hash 和 Goal。主动交接必须经宿主确认 writer_epoch 变化。旧 CLI 保持只读订阅，旧 revision/epoch 写入被拒绝；重复 command_id 不再执行副作用。

Desktop 查看/保存带基线 hash 的草稿、运行相关检查或发后续指令，再交回 CLI。重连按事件水位补齐；超过保留窗口先取快照。模型最后一句“完成”仍显示待验收，失败测试仍可见。跨端接续不得要求用户重新粘贴此前有效目标。桌面关闭、托盘驻留、显式退出、进程崩溃和电脑休眠分别验证，不混成一个关闭事件。

## 5. 研究、采用与真实价值 JRN-04

针对 ISSUE-REUSE-001 冻结问题、当前方案、候选与成功条件。先盘点本地实现，按 15/16 获取固定源码；Jev 的 reuse_selection 建议只依据当前证据。三类来源均做真实访问；合法空结果不伪造候选，缺源不报完整覆盖。对合适候选在隔离目录修改并运行原版/适配版同题测试；REJECT/WATCH/INCONCLUSIVE 同样可以是合法研究成果。

第一轮基线在工作发生时采集，不等 W21 才补写。记录范围、输入、模型和版本、实际工具输出、需要用户重复解释的次数、手工补步骤次数、任务成功与错误、墙钟和未知费用。已有的 Codex 操作记录可以作为有来源的历史观察；若条件不同，不能宣称直接胜出或计算节省比例。W21 只汇总已采集的真实基线。

预注册用户价值硬条件：真实任务交付物满足冻结检查；已保存背景重复索取为 0；原需手工 token 的正常本地使用路径消失；取消/恢复不造成重复写；任何采用结论可以回到源码和实验。速度、费用、质量改善幅度必须实测；无改善允许保留当前稳定方案，不强制输出增长百分比。

## 6. 方向停止条件与不打扰用户

一次失败仍按原两次自动重试、三轮无进展限制处理。另设交付检查点：每完成三张实施任务卡，或连续两个工作回合未形成可观察用户能力，就更新 value_checkpoint；若连续两个检查点只增加文档、fixture 或基础设施，下一步优先解除最短用户流程的缺口，暂停非阻塞性扩展。不能用新论文数、clone 数、测试总数或更换问题编号重置这一判断。

这不是强制缩减已确认范围，也不允许降低安全/恢复/完整验收门。若真实资源不足，明确请求、继续独立工作；没有可继续分支时留下阻塞检查点，不伪称后台运行。无需用户逐库选型、逐测试审批；只在缺本人业务信息、缺授权或确实缺资源时提出具体问题。
